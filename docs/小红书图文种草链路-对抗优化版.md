# 小红书图文种草链路 · 对抗优化版（执行真源）

> **性质**：取代以下两份会话产物作为**执行真源**（原文保留作史料，不再直接按原批次落地）：
> - 《小红书图文生产链路设计方案》（运营通用稿）
> - 《小红书出图链路体检报告与优化设计方案》（技术体检稿）
>
> **裁决一句话**：以「搜索占位资产 × 商务可执行模板 × 矩阵差异化」为运营真源；技术只做**最小充分支撑**。禁止把视频链路 P3 评估器 / 策展诊断双表 / `hotspot_lexicon` 整包复刻到出图链。
>
> **适用**：Buffalo（南非/跨境物流）品牌商务矩阵 · 图文轮播为主 · 纯自然流量 · 核心目标「品牌种草与曝光」。
>
> **现网接缝**：`ai_engine.generate_content` → `xhs_cards.render_carousel` → 审批队列 → `publisher.dispatch` → `adapters.xiaohongshu.XiaohongshuAdapter`（Playwright RPA）。

## 一、第一性原理与目标函数

| 公理 | 含义 | 对设计的约束 |
|---|---|---|
| A1 目标 | 纯自然流量下的品牌种草与曝光 | 搜索可积累 > 单次推荐赌运气 |
| A2 生产者 | 商务本人，非专业内容团队 | 去技能化；系统替人挡事实事故，不替人「创作」 |
| A3 载体 | 图文轮播为主 | 模板工厂优先；AI 是填空机，不是灵感机 |
| A4 矩阵 | 多账号同品牌词占位 | 差异化是存活条件，同质化是全灭条件 |
| A5 品类 | Buffalo 南非/跨境物流 | 时效 / 费用 / 政策类表述 = 品牌事故面 |
| A6 系统现状 | 已有生成 → 渲染 → 审批 → RPA | 增量改接缝，不另起平行宇宙 |

**目标函数（可验收）：**

1. 商务单条笔记从领题到可发布 ≤ 45 分钟（模板填空，而非从零创作）。
2. 每条笔记绑定 `seo_meta`（1 主词 + 2–3 长尾），埋点位置可查。
3. 危险事实表述（日期/数字/政策/时效）无证据则不得进发布队列。
4. 矩阵同文案 / 同素材同日超额发布被系统挡住。
5. 发布失败有显式 reason；周复盘有台账，不依赖自动扒数。

**真正瓶颈排序（对抗后）：**

1. 没有可积累的关键词资产与选题纪律（运营）
2. 矩阵同质化风险未被系统编码（运营 + 轻量技术）
3. 卡片文案事实风险无门禁（技术，真痛点）
4. 配图与选题错配、埋词无结构化（技术，中杠杆）
5. 发布失败可观测性不足（技术；真 P0 在 RPA/账号态，**不在** huimei）
6. 「像视频一样的质量评估器 / 自动数据回流」——现阶段伪需求或过早

**健康度改判（相对原体检 5.5/10）：**  
出图链「能生成 + 能渲染 + 有审批 + 有 RPA」已过半。缺的是**运营操作系统未接入**，以及技术侧 **3 个便宜门禁 + 1 个可观测**——不是差一个视频质量子系统。

## 二、对抗审查结论（六击倒 + 保留清单）

### 击倒 1：huimei「静默失败」不是出图链 P0

- 生产路径：`app.py` → `publisher.dispatch` → `XiaohongshuAdapter`（RPA）。
- `docs/specs/2026-07-01-publish-adapter-framework.md` 明文：**huimei 彻底不用**；`publish_via_huimei` 为死代码保留。
- 原体检把视频链遗留问题原样贴到出图链 → **误诊**。

**改判：** P0 = RPA 失败 reason 不可见 / 账号 cookie 失效 / 无图守卫误报。huimei = P3 卫生清理项。

### 击倒 2：`hotspot_lexicon` ≠ 小红书 SEO 词库

- `hotspot_lexicon.py` 是物流**事件匹配**真源（罢工/港口/清关等），不是搜索意图词库。
- Alias 到 SEO 会污染视频匹配真源。

**改判：** 独立 `xhs_seo_lexicon`（或运营表驱动关键词库）；禁止引用 `hotspot_lexicon`。

### 击倒 3：「真气密」不能整包搬到轮播卡

- 视频链白名单强制只针对「借用清关上下文的完成型宣称」危险面。
- 对图文全页白名单强制 = 毁掉种草多样性，违反 A1/A2。

**改判：**

| 检查 | 模式 | 说明 |
|---|---|---|
| 结构（页数/字数/cover） | 硬气密 | 不合格重试或打回 |
| 广告法绝对化用语 | 黑名单 | 「最」「第一」「100%」等 |
| 物流时效/费用/政策风险句 | `truth_guard` 语义 | 风险句必须有证据或免责；**不是**知识库事实核对 |
| 禁止表述 | — | 「过 truth_guard = 物流事实已校验」 |

### 击倒 4：封面字数规则互相打架

- 运营稿：钩子 3–7 字；技术稿 / 现网 prompt：headline ≤18 字。

**改判（三层不得混用）：**

| 层级 | 约束 | 用途 |
|---|---|---|
| 笔记标题 | 平台标题，可含主词 | 搜索与点击 |
| 封面钩子 | **3–10 字** | 运营可见封面冲击力 |
| 卡面 `headline` | **≤18 字** | `xhs_cards` 渲染约束 |

### 击倒 5：自动「7/30 天拉阅读赞藏」过早

- 无稳定官方开放数据 API；RPA 扒数脆、合规风险高。
- 30 天内人工台账 + 周复盘更真。

**改判：** 台账字段落库 + 人工录入；自动回流另立项，不进前两批。

### 击倒 6：健康度 5.5/10 的尺度误导

见第一节改判。勿用「落后视频一个身位」驱动整包平移。

### 保留清单

**来自运营稿：** 关键词四层、S/A/B 选题占比、模板工厂五类封面、标题公式、四段正文、差异化三硬规则、首小时互动 SOP、48h 判定、周五复盘、红线、30 天启动计划。

**来自技术稿：** 结构兜底、渲染后文件完整性、模板版本号可观测、素材分类配图、`seo_meta` 结构、失败 dump 思路、与审批队列衔接。

**删除/改写：** 「平移视频四件套」总叙事、huimei P0、`hotspot_lexicon` 埋词、真气密全页白名单、自动 7/30 天拉数作 P1、5.5/10 误导表述。

## 三、优化后架构（运营真源 × 技术最小充分）

```
运营层（每周循环）
  关键词库_SEO → 选题池_S/A/B → 人设定位卡 → 差异化规则
       ↑                                              ↓
  周五复盘 ← 发布台账_人工 ←——————— 系统产出/发布结果
       │
       └──→ 加产 / 升模板 / 调词权

系统层（最小充分）
  ai_engine 生成 → 渲染前门禁 → xhs_cards 渲染 → 渲染后完整性
       → 审批队列 → dispatch/RPA → 失败诊断落库
```

**职责切死：**

- **运营层**决定：发什么、谁发、怎么错开、看什么数。
- **系统层**保证：结构合法、危险表述有证据或免责、图能渲、发得出、失败看得见。
- **数据回流**：人驱动先闭环；系统只存台账，不承诺自动拉数。

## 四、运营操作系统（Buffalo / 南非物流化）

### 4.1 账号矩阵（一次性，先做对再放量）

**结构：1 个品牌主号 + N 个商务个人号（KOS）**

| 角色 | 定位 | 内容角度（错开抢流量） |
|---|---|---|
| 品牌主号 | 官方背书、服务能力、资质与动态 | 权威、流程透明、案例背书 |
| 号 A | 跨境卖家视角 · 选购/避坑 | 「南非物流怎么选」「货代避坑」 |
| 号 B | 行业内行 · 节点揭秘 | 港口/清关/仓配节点拆解（**不编造时效数字**） |
| 号 C | 案例型 | 客户路径复盘、对比维度（无实测排名则标「待补资料」） |

**基建清单：** 昵称含品类词（如「Buffalo·XX顾问」）；真实职业照；简介三行（身份 + 能提供什么 + 信任状）；品牌色背景；置顶 1–2 条专业代表作。

**定位原则：** 角度错开，但**共埋同一批品牌/品类关键词**——搜索页多入口占位。

### 4.2 关键词库（四层 · Buffalo 示例）

> 独立运营资产，**不是** `hotspot_lexicon`。初版建议 ≥50 词，每周增补。

| 层 | 类型 | Buffalo 示例 |
|---|---|---|
| L1 | 品类核心词 | 南非物流、南非海外仓、跨境物流南非、Buffalo 物流 |
| L2 | 功效/场景词 | 南非清关怎么做、海外仓入库流程、南非尾程配送、货代怎么选 |
| L3 | 痛点疑问词 | 南非物流是智商税吗、清关延误怎么办、海外仓和直邮区别 |
| L4 | 竞品/替代词 | 仅用于「对比维度」类内容；**禁止无证据的优劣排名** |

每条笔记绑定：`1 主词 + 2–3 长尾` → 写入 `seo_meta`。

**埋词五位置：** 标题、正文前 100 字、标签、首图/封面文案、评论区置顶。

### 4.3 选题池（S / A / B）

| 级别 | 类型 | 占比 | Buffalo 例子 |
|---|---|---|---|
| S | 已验证爆文方向复制放大 | 30% | 「南非清关避坑 3 件事」（验证后矩阵跟进，须差异化） |
| A | 搜索词衍生占位 | 50% | 「海外仓入库要准备什么资料」 |
| B | 人设日常 / 互动 | 20% | 「本周港口动态怎么看（信息核实向）」 |

**选题三标准：** 有搜索意图 / 能自然植入品牌能力（仓、配、关、案） / 竞品同类已验证或痛点真实。

**周一机制：** 负责人出 15–20 题池；每商务领 3–5 题锁定到人。

### 4.4 图文模板工厂（目标 ≤45 分钟/条）

**① 封面模板库（先做 5–10 套）**

| 类型 | 适用 | Buffalo 钩子例（3–10 字） |
|---|---|---|
| 大字报 | 干货/清单 | 「别乱发货」「清关先看这」 |
| 对比图 | 选购/避坑 | 「直邮 vs 海外仓」 |
| 清单体 | 盘点 | 「入库 5 步」 |
| 实拍+标注 | 案例/仓配现场 | 「仓内实拍」 |
| 问答体 | 误区 | 「延误谁的责？」 |

卡面 `headline` 仍 ≤18 字（渲染层）；封面钩子与笔记标题分层。

**② 标题公式（物流化 10 条）**

1. 数字+结果：「3 个动作减少南非清关返工」
2. 痛点提问：「南非海外仓真的有用吗？」
3. 避坑警告：「发南非货千万别先做这步」
4. 身份背书：「做了 X 年南非物流，说点实话」
5. 场景带入：「跨境卖家进南非必看」
6. 对比冲突：「直邮和海外仓到底差在哪」
7. 悬念：「货代最怕你问的 3 个问题」
8. 时效框：「2026 年南非物流避坑框架」（框架≠承诺时效）
9. 反常识：「报价越低越要核节点」
10. 清单体：「南非仓配全攻略，一篇讲清」

**③ 正文四段式**

1. 钩子（≤30 字）：痛点或结果预期  
2. 痛点展开：共情卖家/货主场景  
3. 干货方案：分点；品牌能力**自然出现**；涉及时效/费用必须「以实际单据/官方最新口径为准」  
4. CTA：收藏 / 评论区提问（**不导微信、不加微信号**）

**④ 标签套餐：** 8–10 个 = 2 大词 + 4–5 长尾 + 2 场景 + 1 品牌词；按选题类型成套调用。

**⑤ 素材库：** 仓/配/关/设施实拍、资质、打码案例；按 `asset_taxonomy` 分类（warehouse / delivery / customs / facility / brand）取用，**禁止**清关选题配随机仓储缩略图凑数。

### 4.5 差异化硬规则（防矩阵降权）

1. 同一文案不允许两号原样发布。  
2. 同批素材也必须改封面、标题、角度、正文顺序。  
3. 单号单日 ≤2 条；全矩阵同一天使用同一素材的账号 ≤3 个。

**一材多用：** 同一知识点可变成选购指南 / 避坑提醒 / 对比测评 / 客户路径——每条须像独立创作。

### 4.6 发布与首小时运营

- 节奏：每商务号每周 3–5 条，间隔发；建议固定更新日。  
- 高峰窗：工作日 12:00–13:00、19:00–22:00；周末 10:00–12:00。  
- 首小时：自回置顶评论抛话题；回复全部评论；矩阵真实互动（有质量评论，禁无脑刷赞）。  
- 3 天后查搜索排名：未占位则改标题/换封面重发（须仍满足差异化规则）。

### 4.7 数据监控与复盘

**台账字段（每条一行）：**  
日期 | 账号 | 选题级别 | 标题 | 主词/长尾 | 封面类型 | 阅读 | 赞藏 | 评论 | 涨粉 | 48h 判定 | 备注

**自然流量粗基准（可按账号调）：**  
阅读 <500 未进池；500–2000 正常；2000+ 有爆文潜质。互动率（赞藏评/阅读）≥5% 算优质。

**48h：** 达标 → 追评/系列续篇/他号差异化跟进；不达标 → 记原因进淘汰清单。

**周五 30 分钟：** Top3/Bottom3 → 拆封面/标题/开头/关键词 → 更新选题池、模板库、关键词权重。

### 4.8 红线（Buffalo 特化）

- 不硬广、不导微信号；转化放评论区或主页。  
- 真实人设；勿刷量。  
- **禁止无证据承诺**具体清关时效、费用、放行结果、「已清关完毕」类完成型宣称（与视频链 overclaim 精神对齐，图文侧用风险句+证据/免责，**不用**全页白名单强制）。  
- 对比类内容无实测数据时，必须走「对比框架 · 待补资料」降级（现网 `ai_engine` 已有类似安全路径，应保持）。

### 4.9 前 30 天启动计划

| 阶段 | 时间 | 关键动作 |

| 搭地基 | 第 1 周 | 矩阵基建；关键词库初版 ≥50；5 套封面模板；台账模板跑通 |
| 跑流程 | 第 2 周 | 全矩阵每号 ≥3 条；负责人每日盯台账 |

| 放量 | 第 4 周 | 每号每周至 5 条；爆文方向差异化复制；沉淀可复用模板 |

## 五、系统最小充分支撑

### 5.1 目标链路（修正版）

```
①选题与 seo_meta → ②内容生成 → ③渲染前门禁 → ④卡片渲染
  → ⑤渲染后完整性 → ⑥审批 → ⑦RPA 发布（显式错误）→ ⑧人工台账/复盘
失败 → 诊断落库（轻量，单表或 publish_log 扩字段）
```

### 5.2 各环节技术要点

| 环节 | 做什么 | 明确不做什么 |
|---|---|---|
| ① SEO | 独立词库/表；生成注入 `seo_meta` | 不复用 `hotspot_lexicon` |
| ② 生成 | 强化 image_pages 规则；封面钩子 3–10 / headline≤18；风险表述免责 | 不要求「每页必须含数字」一刀切（空泛口号用内容启发+门禁兜底即可） |
| ③ 渲染前 | 纯函数：结构 + 绝对化用语 + `truth_guard` 风险句（title + 拼接 pages）；失败 `max_calls=2` | 不全页白名单强制；不宣称事实已「校验正确」 |
| ④ 渲染 | 保留 `buffalo-reference-v4`；按 `asset_taxonomy` 分类配图；`TEMPLATE_VERSION` 可观测落库 | 不做 v5 视觉大改（等台账数据） |
| ⑤ 渲染后 | 文件存在、1242×1660、可解码、attachments 齐 | 不做 OCR/对比度/版式 AI 评估；Logo 白像素保留测试，生产可选 warn |
| ⑥⑦ 发布 | RPA reason 硬化；账号就绪态健康检查 | 不修 huimei 主路径；不查 huimei 二进制作为小红书健康检查 |
| ⑧ 台账 | 字段落库 + 人工录入 API/表；周报导出 | 不自动扒小红书后台 |

### 5.3 现网主要触点（待指令批次改代码）

- `ai_engine.py`：规则分层 + `seo_meta` 注入  
- `xhs_cards.py`：配图源扩展、`TEMPLATE_VERSION` 可观测  
- 建议新模块 `xhs_quality_gate.py`：渲染前/后门禁纯函数 + 单测  
- `adapters/xiaohongshu.py` + `publisher.py`：失败 reason  
- `database.py`：台账 / 诊断**最小表**（避免 curation+intake 双表复刻癖）  
- 配图分类：复用 `asset_taxonomy`，不是 `hotspot_lexicon`

## 六、修正后落地批次（指令化）

> 代码未在本设计回合实施。执行前须另开「总指挥指令」批次；批次索引见 `docs/总指挥指令-待开-小红书图文最小充分/README.md`。

### 第 0 批 · 止血（真 P0，约 0.5–1 天）

1. 小红书 `dispatch`/RPA 失败返回显式 reason（未登录、无图、超时、选择器失败）；健康检查报账号就绪态，**不查** huimei。  
2. 渲染/发布失败轻量 dump（单表或扩 `publish_log`）——只记失败现场。

### 第 1 批 · 门禁（真杠杆，约 1–2 天）

3. 渲染前门禁纯函数 + 单测（结构 / 合规 / truth_guard 风险句）+ 有界重试。  
4. 渲染后完整性检查（尺寸/解码/附件齐）。  
5. 封面钩子 / 卡面 headline / 笔记标题三层规则写入 prompt + 门禁常量。

### 第 2 批 · 运营接入（约 1 周，偏产品）

6. 关键词库 + 选题池 → `seo_meta`。  
7. 按 `asset_taxonomy` 分类匹配配图。  
8. 矩阵差异化守卫（文案指纹 / 同素材同日账号上限）。

### 第 3 批 · 台账与复盘（运营为主）

9. 发布台账字段 + 人工录入。  
10. 周复盘导出（Top/Bottom 选题、封面类型、关键词）；**不**自动改模板。

### 明确不做（防漂移）

- 不移植视频 P3 评估器 / `weighted_actionable_score` / 自动重生成  
- 不把 `hotspot_lexicon` 当 SEO 词库  
- 不把 huimei 当发布主路径修复对象  
- 无人工台账数据前不做封面 A/B 实验框架  
- 不做自动扒小红书后台数据（立项另议）  
- 不做「策展 + 入库」双诊断表复刻；失败 dump 保持最小
