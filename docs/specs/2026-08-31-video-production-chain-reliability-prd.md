# 视频生产链路稳定量产 PRD

## 1. 文档信息

- 状态：代码项验收通过；生产量产暂缓（待云端 30/100 实跑与浏览器验收后最终放行）
- 日期：2026-08-31
- 验收结论日期：2026-08-31 11:28:38 CST
- 适用平台：抖音优先，其他平台沿用统一内容与队列模型
- 目标：用户在 AI 对话中输入任意非空话题后，无需手动创建视频项目，即可稳定得到可编辑的视频成片，并由用户决定是否发布
- 实现方：开发模型/工程团队

## 2. 背景与问题

当前视频链路存在四类系统性问题：

1. 生成阶段把模型句式、Hook、素材匹配和质量门禁相互耦合，任意一个环节失败都会导致整条视频失败或永久等待。
2. 项目状态、生成任务状态和实际 MP4 文件不是同一个事实来源，出现 `ready` 但没有成片、`needs_review` 长期阻塞等情况。
3. 素材匹配只在单条任务内去重，没有跨任务冷却和完整序列去重，导致不同话题生成几乎相同的画面。
4. 编辑器、发布队列、抖音账号连接存在多套流程，用户点击后页面不更新，登录页关闭后又被误判为登录失败。

当前云端审计基线：

- 生成任务：102 个成功、106 个失败、13 个长期 `needs_review`、9 个取消。
- 最近任务窗口：17 个成功、3 个失败、1 个取消；3 个失败均卡在第 3 个分镜句子校验。
- 已成功任务中发现 14 组相同素材序列，涉及 36 个任务。
- 发现 5 个项目状态为 `ready` 但没有输出文件。
- 本地测试为 `106 passed / 1 failed`，失败测试使用了未初始化的 SQLite 数据库。

## 3. 产品目标

### 3.1 核心目标

用户只需要：

```text
AI 对话输入话题
→ 系统自动创建项目和生成任务
→ 自动生成脚本、分镜、素材、配音、字幕和 MP4
→ 自动进入内容编辑器
→ 自动生成标题、正文和话题
→ 用户确认后推送发布队列
→ 用户在发布队列点击发布并二次确认
```

### 3.2 必须满足的系统不变量

1. 任意非空、符合安全策略的自定义话题都必须进入生成链路，不要求选择 Hook，不要求先手动创建视频项目。
2. 任何质量检查都不能让任务永久等待；检查失败只能产生 `quality_hold` 或可解释的终态。
3. `ready` 或 `succeeded` 只能表示真实 MP4 已生成、文件存在且可读取。
4. 同一任务失败只能影响当前镜头或当前阶段，不能因为一个分镜格式错误而直接丢弃整条视频。
5. 生成、质量、发布必须是三个独立状态；“有视频”不等于“质量通过”，也不等于“自动发布”。
6. 所有生成结果必须保留项目、版本、任务、素材、文案来源和发布队列之间的可追溯关系。

### 3.3 非目标

- 本期不自动发布到抖音，发布必须由用户确认。
- 本期不删除历史视频、素材、数据库记录；只下线不再使用的功能入口，并保留迁移和审计所需的数据。
- 不通过放宽全部质检规则来伪造“合格片”；低质量片必须明确标记 `quality_hold`。

## 4. 功能需求

### FR-01：AI 对话直接创建视频任务

#### 输入

- `topic`：必填，去除空白后长度大于 0。
- `core_angle`：可选。
- `hook`：可选。Hook 可以是事件、画面或素材，不是脚本必须解释的事件。
- `platform`：默认抖音。
- `duration`：默认 60 秒，允许 50～90 秒。

#### 行为

1. 用户提交后，服务端一次性创建 `video_project`、`revision` 和 `video_generation_job`。
2. 以服务端生成的幂等键防止重复提交，不依赖浏览器 localStorage 判断是否已有项目。
3. 项目创建响应必须包含 `project_id`、`job_id`、当前状态和可轮询地址。
4. 前端立即进入项目页或生成进度页，不显示“请先创建视频项目”。
5. Hook 缺失、不相关或无法匹配素材时，任务仍然继续。

#### 异常

- 空话题：阻止提交并明确提示。
- 明确违反安全政策的内容：允许拒绝，但必须返回可理解的原因和终态，不能无限等待。
- 模型不可用：进入确定性脚本兜底，继续生成视频。

### FR-02：生成链路必须产出视频

各阶段必须支持局部兜底：

```text
脚本规划失败
→ 结构化重试
→ 单镜头修复
→ 确定性镜头模板

素材匹配失败
→ 相关素材
→ 通用物流素材
→ 文字卡/地图/流程图/品牌素材

配音失败
→ 重试
→ 备用音色
→ 无配音但保留字幕的可编辑预览

渲染失败
→ 只重试失败渲染阶段
→ 恢复任务租约
→ 超过次数进入 quality_hold 或 failed
```

输出分类：

| 结果 | 是否有 MP4 | 是否允许进入编辑器 | 是否允许发布 |
|---|---:|---:|---:|
| `succeeded` | 是 | 是 | 由质量门禁决定 |
| `quality_hold` | 是，允许存在质量问题 | 是 | 否，需用户人工接受 |
| `failed` | 否 | 否 | 否 |
| `canceled` | 不保证 | 否 | 否 |

`quality_hold` 不得被当作 `succeeded`，但也不得阻塞用户查看和编辑已经生成的 MP4。

### FR-03：项目、任务、文件状态一致性

建议将以下状态分离存储或由单一事实源派生：

```text
artifact_status: absent | preview | final
quality_status: unknown | passed | hold
publication_status: not_queued | pending_review | queued | published | publish_failed
job_status: pending | running | needs_review | succeeded | failed | canceled
```

约束：

1. `artifact_status=final` 必须有真实文件、可读取视频流和大于 0 的时长。
2. 没有输出文件的项目不得显示 `ready`。
3. `needs_review` 属于人工处理态，不得放进自动任务的 active 状态集合。
4. 项目更新、任务更新、版本更新必须在同一事务或可重试的同步函数中完成。
5. 修复 `update_video_project_revision_payload` 在没有 active job 时引用未初始化变量的问题。
6. 所有时间统一使用 UTC 存储，前端统一按 Asia/Shanghai 展示。

### FR-04：脚本与 Hook 逻辑

#### 内容结构

```text
用户选择的话题/冲突
→ 物流影响
→ 判断维度或解决方法
→ Buffalo 可见动作
→ Buffalo 优势
→ 轻量 CTA
```

#### Hook 规则

- Hook 只承担前几秒的视觉刺激和留存，不要求口播解释 Hook 发生了什么。
- 用户话题是主叙事，Hook 不得覆盖用户话题。
- Hook 与话题无关时，允许保留画面，但不得强行写成新闻播报。
- 禁止在渲染阶段覆盖 MiniMax 已生成的承接文案。
- 只有 MiniMax 接口超时、返回不可解析结果或违反安全策略时，才允许使用确定性兜底。

#### MiniMax 输出要求

每个镜头保存：

```json
{
  "scene_id": "scene-03",
  "voiceover": "……",
  "onscreen_text": "……",
  "copy_source": "model|model_repair|policy_repair|fallback",
  "model_name": "MiniMax-……",
  "repair_reason": null
}
```

报告中逐镜展示 `copy_source`，不能把 `fallback` 伪装成 MiniMax 原始输出。

确定性兜底必须按镜头角色准备多种表达，并使用项目/版本种子轮换，至少覆盖：开场、对比、风险、动作、CTA 五类镜头。

### FR-05：素材多样性与去重

服务端匹配必须同时考虑：

1. 当前任务内素材去重。
2. 最近 20 个成功项目的素材冷却。
3. 完整镜头序列去重。
4. 单素材近期使用次数上限。
5. 视频段、图片、文字卡之间的类型轮换。
6. 资产不足时使用裁剪、镜头范围、字幕版式和文字卡变化补齐，但不得仅靠随机数掩盖相同序列。

验收约束：

- 最近 20 个项目不得出现完全相同的非片尾素材序列。
- 同一素材在最近 10 个项目中的使用次数不得超过 3 次；素材库不足时需在报告中明确标记。
- 生成前计算 `scene_asset_signature`，命中近期完整序列时必须重新匹配。
- 报告列出每个镜头的素材 ID、来源、使用次数和是否处于冷却期。

### FR-06：内容编辑器

“查看成片”必须进入内容编辑器，并携带可靠的 `video_project_id`。

编辑器打开时：

1. 以 URL 中的 `video_project_id` 为唯一事实来源。
2. 从服务端加载当前 revision、真实 MP4 和 publication draft。
3. 不得用旧 localStorage 草稿覆盖当前项目。
4. 自动生成标题、正文、话题，但允许用户修改。
5. 页面显示视频状态、质量状态和每镜头文案来源。

### FR-07：发布队列

统一使用一个入队协议：

```text
POST /api/queue
```

要求：

- 必须携带 `video_project_id`、`revision_id`、视频路径、标题、正文、话题和平台。
- 服务端校验视频路径必须属于该项目当前成功输出。
- 使用幂等键，重复点击只返回同一个队列项。
- 入队成功后前端立即刷新当前项目状态或跳转到该队列项。
- 队列页不能因为默认筛选 `pending_review` 而隐藏刚创建的 `queued` 项。
- 发布按钮只打开确认弹窗；用户确认后才调用真实发布接口。
- 弹窗自动填充标题、正文和话题，用户可在发布前修改。

### FR-08：抖音账号连接

登录成功判定不得依赖用户一直保持创作者平台页面打开。

流程：

```text
扫码登录
→ 获取并持久化有效 cookies/session
→ 校验关键 Cookie
→ 回调服务端确认成功
→ 用户可关闭抖音页面
```

要求：

- 不以 `text=发布视频` 作为唯一成功条件。
- 页面关闭后不能把已取得的登录态判为失败。
- 本地 Agent 不可用、接口不存在、超时、版本过低必须分别提示。
- “重新检测”必须实际检查 Agent 健康状态和会话状态，不能只是重复创建一个已失效页面。
- 服务重启后，已完成的账号登录状态不能依赖内存 session。

### FR-09：移除不再使用的功能入口

下线：

- 热点审核台
- 公众号图文

第一阶段：从导航、路由入口、权限菜单和新用户流程中移除；保留历史数据和只读迁移接口。

第二阶段：确认没有视频生成依赖后，再删除无用前端页面、接口和定时任务。不得直接删除历史数据库表。

## 5. 可观测性

每次任务必须记录：

- `trace_id`、`project_id`、`revision_id`、`job_id`
- 每阶段开始/结束时间、耗时、重试次数
- MiniMax 请求、响应解析结果、模型名和失败原因
- 每镜头 `copy_source`
- 每镜头素材 ID、匹配分数、冷却状态
- 输出文件路径、文件大小、时长和可读性检查结果
- quality gate 结果及阻断原因
- 入队幂等键和最终 queue ID
- 账号登录会话状态和失败阶段

必须提供一个项目级诊断接口或报告，能够回答：

```text
为什么没出片？
现在卡在哪个阶段？
是模型、素材、渲染、账号还是队列问题？
当前文件是否真实存在？
这句话到底来自 MiniMax 还是 fallback？
这个画面最近被使用过几次？
```

## 6. 对抗式测试计划

### 6.1 生成测试

1. 只输入自定义话题，不选择 Hook。
2. 输入与 Hook 完全无关的话题。
3. 输入短话题、长话题、带换行话题和包含列表的话题。
4. MiniMax 返回非法 JSON。
5. MiniMax 第 3 个分镜返回半句话。
6. MiniMax 超时或返回空结果。
7. 素材全部不相关。
8. 素材库只有少量素材。
9. 配音接口失败一次、连续失败和返回短音频。
10. 渲染进程中途退出。
11. Worker 运行中被重启。

### 6.2 前端与队列测试

1. 同一页面连续双击入队。
2. 入队后刷新页面。
3. 从旧项目 URL 打开编辑器。
4. 浏览器 localStorage 存在旧草稿时打开新项目。
5. 队列当前筛选为 `pending_review` 时创建 `queued` 项。
6. 从编辑器入队后返回队列并定位到当前项目。
7. 点击发布但取消确认，不得真正发布。

### 6.3 账号测试

1. 扫码成功后关闭抖音创作者平台页面。
2. 本地 Agent 未安装。
3. 本地 Agent 未启动。
4. Agent 版本过低。
5. Agent 接口返回 404。
6. 登录过程中刷新页面。
7. 服务重启后检查已连接账号。

## 7. 验收标准

### 必过门槛

- 30 个不同自定义话题连续生成：不得出现永久等待。
- 每个非空话题必须得到 MP4，或明确的 `quality_hold`/`failed` 终态和可解释原因。
- 不得出现 `ready` 但没有输出文件。
- 第 3 个分镜句子错误不能再直接终止整条任务。
- 最近 20 个项目不得出现相同完整素材序列。
- MiniMax 可用时，成功报告必须显示实际模型调用和逐镜来源。
- 质量不通过的片子可以进入编辑器，但不能标记为可直接发布。
- 入队后页面立即可见队列项，重复点击不产生重复记录。
- 关闭抖音登录页面后，已取得的登录态仍然有效。
- Worker 重启后，过期任务能在 30 秒内自动恢复或进入终态。

### 发布前质量门槛

- MP4 可播放。
- 视频时长在目标范围内。
- 字幕时间线与音频/画面一致。
- 无连续重复镜头。
- 标题、正文、话题已生成。
- 项目、视频、编辑器和队列关系可追溯。

### 2026-08-31 验收结论

- 代码项可以通过：Hook 非门禁、近 20 条序列重选/降级、入队入口统一、完整分支可复现、全量 pytest 0 failed。
- 生产量产项暂缓：未完成云端 30 条不同话题与 100 条 MiniMax 实跑，未完成浏览器端完整点选验收。
- 最终放行条件：完成上述云端实跑和浏览器验收后，才能称为稳定量产通过。

1. 统一状态机和事实源，先修复 `ready` 无文件、长期 `needs_review`、任务恢复。

- 不要简单把所有质检门槛改成通过。
