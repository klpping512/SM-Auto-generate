# 热点视频事件拆分与双素材库联动设计

## 目标

将下载后的南非热点视频从“通用素材分类”中隔离出来，按新闻事件拆分、命名并建立可复用的事件片段；每个事件再与 Buffalo 原有素材库匹配，供视频成片组合使用。

本次设计解决四个问题：

1. 热点下载视频被错误归类为“配送”等业务分类。
2. 两分钟热点视频只按视觉场景切成碎镜头，无法判断每段对应什么事件。
3. 事件片段没有名称，运营人员无法检索、理解和选择。
4. 热点真实画面与 Buffalo 原有素材没有形成事件级匹配关系。

## 核心原则

### 来源和内容分类分离

- `library_origin` 表示素材来自哪里：`hotspot` 或 `owned`。
- `business_category` 表示画面内容：配送、仓库、品牌、人员等。
- 热点素材的来源属性固定为 `hotspot`，不得被通用分类器覆盖。
- Buffalo 自有素材的来源属性固定为 `owned`。
- “热点素材”不是业务分类，不能与“配送”“仓库”放在同一个字段中竞争。

当前数据库已有 `assets.hotspot_id`，MVP 以该字段作为热点来源的权威判断，不增加重复来源字段；API 对外统一返回派生字段 `library_origin`。

### 两级切分

热点视频处理为两层：

1. **事件片段**：一个完整新闻事件，目标长度 12～25 秒。
2. **镜头片段**：事件内部的可编辑画面，目标长度 3～8 秒。

事件片段负责“讲的是什么”，镜头片段负责“剪辑时用哪一段”。

不得仅按固定时间机械切分事件。事件边界综合使用：

- 原生字幕或 ASR 时间戳；
- 画面标题、地点和机构 OCR；
- 地图页、标题卡、主持人口播转场；
- 现有场景变化边界；
- 连续镜头中的地点、人物和机构变化。

MVP 优先使用本地规则和已有 ASR/OCR 证据，不默认调用 MiMo。证据不足时允许生成“待确认事件”，不得编造事实。

## 事件识别规则

### 边界候选

以下任一条件可作为新事件候选：

- 出现新的地点标题或省份名称；
- 出现新的机构、人物或事件标题；
- 地图/栏目转场后进入新现场；
- 字幕主题发生明显变化；
- 场景变化且距离上一事件开始已超过 12 秒。

### 合并与长度约束

- 小于 6 秒的候选默认与相邻事件合并。
- 目标事件长度为 12～25 秒。
- 单个事件最长 35 秒，超过时按次级转场拆分。
- 事件不得跨越明确的地点或主题变化。
- 每个事件关联其包含的现有 `asset_segments`，不重复生成底层视频文件。

### 低置信度

无法可靠识别事件时：

- 标题使用 `待确认事件 NN`；
- 保留时间范围、来源和证据；
- 标记 `review_required`；
- 不进入自动成片，只能人工确认后使用。

## 双语命名

每个事件保存中文标题和英文标题。

展示格式：

```text
2026-07-22｜开普敦｜Transnet 土地占用事件｜SA Today
2026-07-22 | Cape Town | Transnet Land Occupation | SA Today
```

名称字段来源优先级：

1. 原视频标题卡或字幕中的明确事件名；
2. OCR/ASR 中的地点、机构和动作组合；
3. 热点标题与事件时间范围；
4. `待确认事件 NN｜00:31–00:45｜SA Today`。

自动生成标题时必须满足：

- 不补充证据中不存在的人物、数字和因果关系；
- 中文标题与英文标题表达同一事实；
- 地点不明确时省略地点，不猜测；
- 标题控制在中文 30 字、英文 80 字以内。

## 数据结构

新增 `hotspot_event_clips`：

```text

asset_id

end_ms

title_en

```

新增 `hotspot_event_segment_links`：

```text

```

事件记录只引用现有热点视频和镜头，不复制视频文件。预览通过原视频的起止时间播放，避免增加服务器容量。

## 分类修复

热点下载完成后：

- 资产级 `category`、`primary_category` 默认为 `other`；
- 不再根据地图、道路等弱证据把整条热点视频归为 `delivery`；
- 镜头仍可保留内容语义标签，但 UI 必须同时显示“热点来源”；
- 热点事件的地点、机构和主题进入事件字段，不覆盖来源属性。

对已有热点资产提供一次性重建：

- 找出 `hotspot_id IS NOT NULL` 的视频；
- 重置错误的资产级业务主分类为 `other`；
- 保留原镜头和标签作为证据；
- 重新生成事件片段和名称。

## 与 Buffalo 原有素材库联动

每个事件形成一个匹配查询：

```text
地点 + 机构 + 事件动作 + 业务影响 + 画面需求
```

匹配范围：

- 热点现场镜头候选：仅当前事件包含的热点镜头；
- 品牌证明镜头候选：仅 `owned` 原有素材库；
- 两类候选不得互相替代。

每个事件输出：

- 热点事件镜头 Top 3；
- Buffalo 原有素材 Top 3；
- 匹配理由；
- 不匹配原因；
- 推荐的成片职责。

默认成片结构：

```text
热点现场/事实钩子 30%
Buffalo 履约、仓储、配送或品牌证明 70%
```

30/70 是整条样片的目标比例，不要求每个事件机械满足。若某事件与 Buffalo 业务无可靠关联，应标记“不建议成片”，不得强行拼接。

## 前端结构

热点素材卡片在下载完成后显示“事件片段”入口。

事件列表每张卡片展示：

- 中文标题；
- 英文副标题；
- 时间范围和时长；
- 地点、人物、机构；
- 识别置信度和待确认状态；
- 包含镜头数量；
- Buffalo 原有素材 Top 3；
- 预览事件片段；
- 应用到成片。

原本素材库继续管理 Buffalo 自有素材。热点素材库继续管理热点来源、下载状态和事件片段。两库通过事件匹配结果联动，不合并成一个混乱列表。

## 处理流程

```text
热点视频下载
→ 原视频入热点素材库
→ 场景检测、ASR、OCR
→ 事件边界识别
→ 双语事件命名
→ 人工确认低置信度事件
→ 每个事件匹配 Buffalo 原有素材 Top 3
→ 选择事件与品牌证明镜头
→ 进入现有视频生成流程
```

## 成本控制

- 事件拆分默认使用本地 ASR、OCR、场景检测和规则，不调用 MiMo。
- 双语标题优先使用已有热点翻译和本地词典。
- 只有低置信度且用户主动点击“智能补全”时才允许调用可替换文本模型。
- 事件预览不生成新视频文件，使用原视频起止时间播放。
- Top 3 匹配复用现有语义匹配服务，不新增模型调用。

## 异常与降级

- 没有字幕：使用 OCR、场景变化和地点标题识别。
- OCR/ASR 质量差：生成待确认事件，不编造标题。
- 没有明显事件边界：按 20 秒上限生成待确认候选。
- 原有素材无匹配：显示“暂无可靠品牌素材”，不强制返回结果。
- 视频重新分析：事件记录按处理版本重建，人工确认标题可选择保留。

## 验收标准

以素材 298 为基准：

- 资产来源显示为“热点素材”，不得再显示为“配送素材”。
- 120 秒摘取被组织为多个新闻事件，而不是只有 17 个无名称镜头。
- 每个事件均有中文标题、英文标题、时间范围和证据。
- 低置信度事件明确显示“待确认”。
- 每个合格事件最多展示 3 个热点镜头和 3 个 Buffalo 原有素材。
- 无可靠匹配时返回空结果和原因。
- 事件预览不额外复制视频文件。
- 默认处理不调用 MiMo。
