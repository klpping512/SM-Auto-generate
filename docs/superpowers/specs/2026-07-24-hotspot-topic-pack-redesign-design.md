# 南非热点专题包工作台重设计

日期：2026-07-24  
状态：设计评审中  
目标：把热点模块从“单条新闻 + 四步向导”改成“事件级专题包”，聚合多平台信号、事实、图片、视频、纯文本和权利状态，再把已确认的专题包交给内容生产。

## 1. 现状与问题

当前热点页已经具备双语、可信源、图片/视频/纯文本标签和素材库入口，但核心对象仍然是单条热点记录。由此产生四个问题：

1. 同一个事件在 SABC、News24、GDELT、YouTube 出现时会被拆成多条热点，无法判断事件是否真正升温。
2. 事实来源、媒体素材、素材权利和 Buffalo 物流切入角度分散在页面不同步骤里，用户不知道先确认什么。
3. “抓取”容易被理解成“下载全部视频”，会造成服务器容量和版权风险；实际应该先保存信号和链接，确认后再处理具体媒体。
4. 热点与成片的连接缺少中间层，容易把不相关素材直接拼入视频。

本次重设计不改变已有的素材库、视频跟进和质量门禁，而是把热点页的核心对象改成“热点专题包”。

## 2. 核心概念

### 2.1 热点专题包

一个专题包代表一个真实事件，不代表一篇文章。专题包可以包含：

- 中英文事件标题和摘要；
- 事件类型、城市、人物、机构、关键词；
- 热度分、升温状态和最后更新时间；
- 多个可信来源信号；
- 图片候选、视频候选、纯文本事实；
- 每个媒体的权利状态、来源链接和下载状态；
- Buffalo 物流/商业相关度和可用内容角度。

### 2.2 原始信号

每次来源采集先产生原始信号，不立即生成素材。信号包括标题、摘要、URL、来源、发布时间、平台数据和抓取时间。多个信号经过事件聚类后归入一个专题包。

### 2.3 媒体素材

媒体素材分为三种形式：

- 视频：YouTube、TikTok、新闻视频等；
- 图片：新闻封面、文章配图、开放许可图片；
- 纯文本：标题、摘要、原文片段和结构化事实。

三种形式都必须显示对应标签，不能只显示“素材”。

## 3. 来源范围与采集策略

第一版固定接入四类稳定来源：

1. Google Trends 南非区：发现搜索量突然增长的关键词。
2. SABC、News24、eNCA 等本地新闻 RSS/网页：获得可信事实和发布时间。
3. GDELT：补充跨媒体报道、图片线索和转载扩散。
4. YouTube 南非热门和已配置频道：获得公开视频链接、频道、缩略图、时长和互动数据。

TikTok、X、Instagram 第一版只保存可追踪链接和信号，不作为全自动下载源。只有进入人工确认流程的媒体，才允许进入下载、抽帧、转写和切片处理。

采集任务默认每 15 分钟运行一次；单个来源失败只影响该来源，并在信源健康面板中显示，不阻断其他来源。

## 4. 事件聚类与热度评分

每条信号提取标题、摘要、人物、公司、城市、事件类型和关键词。满足以下条件时归入同一个专题包：

- 多语言标题/摘要语义相似度大于 0.82；
- 至少共享一个人物、公司、城市或核心实体；
- 发布时间相差不超过 48 小时。

无法自动确认的信号进入“待合并”状态，由用户手动合并或拆分，不能静默合并。

热点分采用 100 分模型：

```text
搜索增长速度       25%
本地媒体覆盖数量    20%
跨平台出现数量      15%
视频播放增长速度    15%
事件新鲜度          10%
物流/商业相关度     10%
图片/视频丰富度      5%
```

状态分为：正在升温、稳定、降温、待确认。评分依据和参与来源数量必须在专题包中可见，不能只展示一个黑箱分数。

## 5. 专题包页面结构（B 方案）

页面采用“左侧专题包列表 + 右侧当前专题包详情”，移除当前页面的强步骤向导。

### 5.1 左侧列表

每张专题包卡片展示：

- 中英文事件标题；
- 热点分和升温状态；
- 事件日期；
- 事件类型/城市；
- 视频、图片、纯文本数量；
- 主要来源数量；
- 物流相关度；
- 当前状态：待确认、已确认、已入热点库、已进入内容任务。

筛选项：日期、来源、事件类型、升温状态、素材形式、物流相关度。

### 5.2 右侧详情

详情按照信息优先级排列：

1. 事件摘要：中英文标题、摘要、时间、地点、来源数量和热点分。
2. 信号时间线：展示 SABC、News24、GDELT、YouTube 等信号及其发布时间。
3. 素材区：视频、图片、纯文本三个标签页；每个媒体显示预览、来源、发布时间、权利状态和操作。
4. 物流关联：展示系统识别的候选主题，例如末端配送、路线风险、港口/清关、电商增长、履约稳定性；每个主题必须有对应事实依据。
5. 出库动作：确认并入热点库、生成视频跟进、生成图文、仅保存链接、打开原文。

页面首要动作是“确认专题包”，不是“下载全部素材”。

## 6. 权利与下载规则

每个媒体使用以下权利状态：

- `owned`：Buffalo 自有素材；
- `licensed`：已取得授权；
- `creative_commons`：有明确许可；
- `internal_preview`：仅内部预览/研究；
- `link_only`：只保存链接；
- `unknown`：权利不明确。

新闻图片、YouTube、TikTok、X 视频默认进入 `internal_preview` 或 `link_only`。确认并入热点库只确认“专题包可用”，不自动改变媒体权利状态。

下载策略：

- 默认保存元数据、缩略图或低清预览和原文链接；
- 人工确认某个视频后，才下载低清分析副本；
- 低清副本只用于关键帧、字幕、OCR 和事件切片；
- 服务器只保留低清副本、切片、关键帧和转写文本，原始链接长期保留；
- 已使用且无项目引用的分析副本按 7–14 天清理，仍被项目引用的文件保留到项目结束。

## 7. 与内容生产的联动

专题包确认后，内容生产不直接读取所有媒体，而是通过“证据选择器”读取：

```text
热点专题包
    ↓
选择与物流主题相关的事实和媒体
    ↓
匹配 Buffalo 原有素材库
    ↓
生成视频/图文/公众号任务
```

视频跟进规则保持当前质量门禁：

- 默认总时长 60 秒；
- 至少 3 个热点视频事件片段；
- 至少 4 个 Buffalo 原有视频片段；
- 图片占比不超过 15%；
- 不允许连续静态图片；
- 每个片段保存来源、时间范围、事件 ID 和匹配理由；
- 证据不足时阻止生成，不用弱相关素材补齐。

热点专题包只提供事实和外部事件证据；Buffalo 的时效、安全、便捷等品牌表达仍然只能来自已确认的品牌证据和原有素材库。

## 8. 数据与接口改动

采用增量改造，不删除现有 `hotspots`、`hotspot_media`、`hotspot_sources` 和 `hotspot_event_clips` 数据。

### 8.1 数据字段

在 `hotspots` 增加专题包状态字段：

- `heat_score`；
- `heat_state`；
- `event_type`；
- `locations_json`；
- `entities_json`；
- `signal_count`；
- `media_count`；
- `logistics_relevance`；
- `package_status`。

新增 `hotspot_signals` 表保存原始信号，字段包括：

- `hotspot_id`；
- `source_name`、`source_type`、`external_id`；
- `title`、`summary`、`source_url`；
- `published_at`、`retrieved_at`；
- `metrics_json`、`raw_payload_json`；
- `cluster_status`。

### 8.2 接口

- `GET /api/hotspot-packages`：专题包列表和筛选；
- `GET /api/hotspot-packages/{id}`：专题包详情、信号、媒体和物流角度；
- `POST /api/hotspot-packages/{id}/confirm`：确认专题包；
- `POST /api/hotspot-packages/{id}/merge`：合并待确认信号；
- `POST /api/hotspot-media/{id}/prepare`：对单个确认媒体启动下载/分析；
- `POST /api/hotspot-packages/{id}/create-content-task`：创建视频或图文任务。

已有 `/api/hotspots` 和 `/api/hotspot-media` 保留兼容，旧链接继续可用。

## 9. 异常、成本和容量控制

- 来源超时：记录来源级错误，继续处理其他来源。
- RSS/网页结构变化：保留原始链接和失败原因，禁止伪造标题或图片。
- YouTube API Key 缺失：显示“仅链接采集”，不阻断新闻来源。
- 事件聚类置信度不足：进入待合并，不自动合并。
- 图片或视频下载失败：保留链接和缩略图，不把专题包标为失败。
- 服务器空间不足：先清理未引用的低清分析副本，再暂停新下载。
- MiMo 只用于需要语义判断的步骤，热度计算、来源计数、媒体统计和下载状态均采用确定性代码。

## 10. 验收标准

1. 同一事件来自至少三个来源时，界面显示为一个专题包，并能展开查看所有信号。
2. 每个专题包清晰区分视频、图片、纯文本，并显示来源、日期和权利状态。
3. 点击“确认并入热点库”后，只确认专题包，不自动下载所有外部视频。
4. 只对人工确认的单个媒体执行下载、抽帧、转写和事件切片。
5. 生成视频任务时，能看到所引用的热点片段和 Buffalo 原有素材，并通过 60 秒证据门禁。
6. 来源失败、下载失败和聚类不确定不会导致整个热点页不可用。
7. 100GB 服务器不保存无审批的原始视频，低清缓存和无引用文件可自动清理。

## 11. 不在本次范围内

- 不做 TikTok、X、Instagram 的无授权批量下载。
- 不把外部新闻素材默认标记为可商用。
- 不重写现有视频渲染器、MiMo 调用协议和发布适配器。
- 不一次性引入 PostgreSQL、Redis、MinIO 等基础设施；先在现有 SQLite/文件存储上完成 MVP。
