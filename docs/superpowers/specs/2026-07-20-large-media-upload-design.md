# 大体积共享素材上传设计

## 目标

让管理员通过素材库可靠上传单个不超过 2 GiB 的图片或视频，显示逐文件进度并保持公共素材库、哈希去重、缩略图和分类逻辑。将桌面“视频素材”首批约 3.2 GB 文件按子目录同步至服务器并批量入库。

## 方案选择

采用“单请求流式上传 + 首批 rsync 导入”。不采用整文件内存读取，因为 100–500 MB 视频会放大内存压力；暂不采用分片断点续传，因为当前最大文件不足 500 MB，复杂度和收益不匹配。

## 后端

- 图片上限保持 10 MiB，视频上限提高到 2 GiB。
- `UploadFile` 按固定块读取并写入临时文件，累计字节超过上限时立即停止并返回明确错误。
- 文件验证、ffprobe、SHA256 去重、正式存储和缩略图仍复用 `media_assets.ingest_file`。
- 临时文件无论成功或失败都删除。
- Nginx `client_max_body_size` 提高到 2 GiB，并延长请求超时。

## 前端

- 使用 `XMLHttpRequest` 获取真实上传进度事件；认证令牌继续放在 Authorization 请求头。
- 多文件按顺序上传，展示当前文件名、百分比和总进度，避免多个大文件并发占满带宽与内存。
- 选择前即检查扩展名和大小；错误信息持续展示，不依赖三秒 Toast。
- 上传结束刷新素材列表；单个文件失败不阻断后续文件。

## 首批导入

- 仅同步桌面“视频素材”中的 MP4、MOV、WebM、JPG、JPEG、PNG、WebP。
- 排除 `.DS_Store`、`._*` 和其他隐藏元数据。
- 保留子目录，服务器目标为 `/opt/distribution-manager/static/assets/import/`。
- 通过管理员导入接口扫描；成功后文件移动到正式素材库，SHA256 重复项跳过。

## 验证

- 自动测试证明大于旧 50 MiB、小于 2 GiB 的上传采用分块读取并成功入库。
- 自动测试证明超过上限立即失败且临时文件清理。
- 前端静态测试验证进度 UI、XHR progress 和顺序队列。
- 服务器验证服务状态、Nginx 配置、素材数量、总大小和页面 API。

## 已知边界

- HTTP 访问不提供传输加密；此次不增加域名或付费服务。
- 单请求上传不支持浏览器关闭后的断点续传。
- 素材库为团队共享，只有管理员可上传、编辑和删除。
