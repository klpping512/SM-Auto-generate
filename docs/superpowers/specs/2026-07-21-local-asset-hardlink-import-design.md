# 本地素材硬链接接入与可观察处理设计

## 1. 决策

采用用户确认的方案 A：将桌面 `/Users/ylanlll/Desktop/视频&图片素材/` 作为受信任的本地素材根目录，通过硬链接接入应用管理的 `static/assets/library/`，不复制约 5.9GB 原始文件，不修改或删除源目录内容。

本阶段只解决四个问题：批量接入、处理进度、取消任务、视频匹配阶段可解释。暂不上传服务器，不把 IOL 媒体下载到素材库，不增加复杂 Agent 或独立向量数据库。

## 2. 当前基线

- 源目录共 262 个文件，约 5.9GB：118 个 MOV、143 个 JPG、1 个 HEIC。
- 当前数据库只有 28 个素材、16 个启用素材和 30 个镜头，新目录尚未接入。
- 最新视频任务停在 `match_quality_check`，五个镜头匹配分为 6.08–19.75，低于现有 75 分门槛。
- 页面把 `needs_review` 表现成持续等待，且本地服务停止后没有明确的失联提示。

## 3. 接入方式

### 3.1 受信任根目录

- 默认根目录为 `~/Desktop/视频&图片素材`，可由 `LOCAL_ASSET_ROOT` 环境变量覆盖。
- 后端只扫描该根目录之内的普通文件，拒绝路径穿越和根目录之外的输入。
- 支持 JPG、JPEG、PNG、WebP、MP4、MOV、WebM；当前 1 个 HEIC 明确计入“不支持格式”，不静默丢失、不自动付费转换。

### 3.2 硬链接

- 新文件在素材库中创建硬链接，保留现有相对路径数据模型、静态服务和 FFmpeg 渲染链路。
- 硬链接失败时不自动复制 5.9GB；任务记录失败原因，由管理员决定是否单独上传该文件。
- 删除应用素材只删除应用侧链接和数据库记录，不删除桌面源文件。
- SHA256 继续用于去重；已存在素材计入“重复”，不新建处理任务。

## 4. 持久化批量任务

新增本地导入批次，固定保存：任务 ID、根目录、状态、阶段、总数、已扫描数、成功数、重复数、跳过数、失败数、当前文件、取消请求、错误摘要和时间戳。

任务状态：

```text
pending → scanning → importing → processing → succeeded
                         ↘ cancel_requested → canceled
                         ↘ failed
```

- 创建任务立即返回 `202`，浏览器不等待 262 个文件完成。
- 同一根目录同一时间只允许一个活动任务，重复点击返回现有任务。
- 每处理一个文件更新一次进度；前端每 1–2 秒轮询。
- 取消是协作式取消：完成当前文件后停止，不留下半条数据库记录。
- 服务重启后，未完成批次标记为 `interrupted`，允许重试；页面不得继续显示“处理中”。

## 5. 分层处理

为避免 118 个视频同时执行 FFmpeg：

1. 接入阶段只做格式校验、ffprobe、哈希、硬链接和缩略图。
2. 接入成功后创建单素材语义处理任务，由现有并发上限 2 控制。
3. 图片直接形成一个镜头；视频按现有 2–8 秒规则切分并抽取代表帧。
4. 前端分别显示“已入库”和“已分析”，不能把入库完成冒充分析完成。
5. 未分析素材不可进入发布级成片，但可以在素材库中查看并等待处理。

## 6. 视频第三步状态

- `needs_review` 必须显示为“匹配质量不足，等待人工处理”，不能显示为持续生成。
- 展示最低匹配分、门槛和每个镜头的问题。
- 服务轮询连续失败时显示“本地服务已断开”，停止无限转圈。
- 新素材处理完成后，用户从原项目重新匹配；旧任务保持审计记录，不篡改其结果。
- 匹配门槛必须与评分量纲一起校准，不能只把 75 改成更低数字掩盖弱匹配。

## 7. IOL 来源边界

- `https://iol.co.za/news/south-africa/` 作为热点发现页，RSS 为 `https://www.iol.co.za/rss`。
- IOL 属于二级媒体发现源，不作为单独证明具体事实的官方证据源。
- 系统只保存标题、原文 URL、发布者和时间；关键事实需回查官方机构或第二个独立来源。
- IOL 条款要求商业使用内容或 RSS 取得许可，因此当前不自动抓取全文、不自动下载图片和视频、不进入素材库。
- 现有最多 5 个自动官方可信源规则保持不变；IOL 以受限发现链接存在，不占用官方证据源名额。

## 8. 验收

1. 创建本地导入任务后 1 秒内返回任务 ID，页面显示真实文件级进度。
2. 262 个源文件均被计入成功、重复、跳过或失败，四类之和等于总数。
3. 应用侧视频与源文件 inode 一致，证明使用硬链接；源目录总大小不因导入翻倍。
4. 取消任务后不再处理新文件，已完成文件保持可用。
5. 服务重启后旧任务显示中断并可重试，不无限转圈。
6. 素材入库数、语义处理数和失败数分开展示。
7. 视频匹配暂停时显示具体问题，不再伪装成“仍在生成”。
8. IOL 只保存链接和来源属性，不下载媒体、不作为唯一事实依据。

## 9. 非目标

- 不向服务器同步 5.9GB 素材。
- 不删除或移动桌面源文件。
- 不在本阶段支持 HEIC 转换。
- 不在本阶段增加断点续传、分布式队列或外部向量数据库。
- 不自动突破 IOL 的商业授权边界。
