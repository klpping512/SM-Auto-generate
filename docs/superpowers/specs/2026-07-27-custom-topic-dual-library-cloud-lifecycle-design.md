# SA-LogiFlow 自定义选题、双素材库与云端生命周期实施方案

日期：2026-07-27  
状态：方案已确认，待拆分实施  
适用范围：热点选题、AI 对话、内容编辑器、热点素材库、Buffalo 原本素材库、视频生成、云服务器部署  
目标读者：产品负责人、后端与前端开发者、测试人员、部署与运维人员

## 1. 文档目标

本方案统一解决以下问题：

1. 用户可以自由输入“南非物流”“南非清关与末端配送风险”等选题，不被固定话题选择器限制。
2. 热点事实、热点媒体、Buffalo 原本素材和品牌证据按职责关联，不混成一个不可解释的素材池。
3. 热点采集由系统持续执行，热点媒体下载和内容生成由真实用户意图触发。
4. 热点基础事实可以共享，企业授权素材和个人选题状态保持正确的数据边界。
5. 单次内容任务有明确的模型调用、Token、素材召回和重试预算。
6. 云端持续运行时，临时文件、热点缓存、草稿、成片、模型缓存和日志不会无限占用磁盘或内存。
7. 方案能够在当前 SQLite、文件存储和 FastAPI 基础上渐进实施，不要求第一阶段引入复杂分布式基础设施。

本方案不以“素材库越大越好”为目标。最终目标是稳定生成事实可信、画面相关、品牌表达有依据、成本可预测的内容。

## 2. 最终产品决策

### 2.1 选题决策

- 固定话题选择器继续保留，但只作为快捷模板。
- 用户自由输入的话题是内容任务的第一等输入。
- 自由输入先形成结构化“选题简报”，再检索事实和素材，不直接把一句宽泛话题送给模型生成全文。
- 当话题过宽时，系统先返回 2～3 个有证据支持的角度；用户选择或修改后才生成完整内容。
- 没有近期可靠热点时，明确标记为“常青选题”，不得用无关新闻伪装热点。

### 2.2 热点采集决策

- 系统持续采集的是热点线索和元数据，不是完整媒体文件。
- 未被用户选择的热点默认只保存标题、摘要、来源、URL、发布时间、热度和媒体链接。
- 用户确认某个选题或专题包后，系统才推荐与之相关的媒体。
- 只有权利状态允许且用户明确确认的单个媒体，才下载低清分析副本并进入抽帧、OCR、ASR、转写和事件切片。
- 不执行“定时批量下载所有热点视频”“定时生成所有热点成片”。

### 2.3 素材库决策

- 热点素材库和 Buffalo 原本素材库物理与逻辑上继续分开。
- 内容任务通过“任务级证据包”同时引用两个库，不把两个库永久合并。
- 热点素材只证明外部事件和背景。
- Buffalo 原本素材和品牌证据只证明企业流程、能力和实际动作。
- 同一个文件在企业范围内只保存一份，多个用户和项目通过引用复用，不复制文件。

### 2.4 共享边界决策

- 热点事实底池共享：同一事件的来源、时间、标题、摘要、聚类和热度不因用户不同而重复计算。
- 企业热点证据库共享：企业确认过的权利状态、低清分析副本、事件片段和转写结果在企业内部复用。
- Buffalo 原本素材库企业内共享，不对其他企业开放。
- 用户的自定义选题、收藏、忽略、推荐排序、草稿和生成历史按个人保存。
- 当前单企业部署先以“全局热点事实＋企业素材＋`created_by` 个人工作区”实现；未来 SaaS 化时再增加 `tenant_id`，不得用个人账户隔离代替企业隔离。

### 2.5 成本与生命周期决策

- 一个普通选题任务默认最多 3 次远程模型调用。
- 单任务默认总输入不超过 12,000 Token，总输出不超过 3,000 Token。
- 系统默认只生成用户选择的平台，不再默认一次生成全部平台。
- 大文件默认可淘汰；事实、来源、权利、标签、转写和引用记录长期保留。
- 云服务器本地磁盘只承担工作缓存，长期原始素材和置顶成片后续迁移到对象存储。
- 任何“永久保留”数据都必须计入企业配额；置顶不能绕过容量上限。

## 3. 第一性原理

### 3.1 内容质量是木桶，不是平均分

一份内容的可用性取决于以下最弱项：

- 选题是否清楚；
- 事实是否可靠；
- 热点是否真正相关；
- 品牌表达是否有内部证据；
- 画面是否匹配分镜；
- 媒体权利是否允许；
- 输出是否适合目标平台。

任何硬门禁失败，都不能通过增加模型调用、扩大上下文或填入弱相关素材来弥补。

### 3.2 计算应在价值确定后发生

采集标题、来源、发布时间和公开指标成本低，可以持续执行。下载视频、视觉分析、转写、生成旁白和渲染视频成本高，只能在用户已经表达真实内容意图后执行。

### 3.3 可重建文件不应永久保存

需要长期保留的是：

- 事实来源和权利证据；
- 文件指纹和对象引用；
- 结构化标签、转写和事件时间范围；
- 用户确认过的选题简报与证据包；
- 已发布内容的必要审计记录。

热点低清副本、关键帧、转码文件、预览和过期成片属于可重建数据，应按生命周期自动淘汰。

### 3.4 无限生成与有限磁盘不能同时成立

如果允许所有文件永久保存、允许用户无限置顶且不设置配额，任何容量的服务器最终都会写满。因此系统必须同时具备：

1. 源头按需生成；
2. 数据分级保留；
3. 引用感知清理；
4. 企业和用户配额；
5. 任务启动前容量准入；
6. 达到水位后的自动降级和熔断。

## 4. 当前基础与主要缺口

### 4.1 可以复用的现有能力

- `static/editor.html` 和 `static/chat.html` 已允许用户输入自定义需求。
- `hotspot_topic_packages.py` 已有确定性信号标准化、事件聚类和热度计算。
- `hotspot_media` 已实行“发现链接 → 确认权利 → 下载分析”。
- `semantic_matching.py` 已区分热点事实镜头和 Buffalo 品牌镜头。
- `model_router.py` 已有模型角色、调用预算、Token 记录和缓存键。
- `media_retention.py` 已支持热点源文件 7 天、成片 30 天、置顶保护、活动引用保护和磁盘水位检查。
- `scheduler.py` 已注册每日媒体生命周期任务。

### 4.2 需要解决的缺口

1. `hotspot_logistics_planner.py` 仍把热点映射到少量固定物流主题，自由输入没有贯穿热点视频链路。
2. 当前话题仍以字符串传递，缺少受众、角度、地区、时间、目标平台和事实边界。
3. 热点专题包、企业原素材和品牌证据之间缺少可保存、可审查的任务级关联对象。
4. 当前默认生成多个平台，容易产生不必要的模型调用和输出。
5. 清理任务默认 `dry-run`，生产环境如果不切换将只报告、不释放空间。
6. 当前生命周期主要覆盖热点源文件和最终成片，未完整覆盖临时文件、关键帧、转写缓存、失败任务、模型缓存和日志。
7. 磁盘只在剩余空间低于固定百分比时阻止任务，没有估算单个任务峰值和运行中预留。
8. 没有企业素材配额、热点缓存配额、用户成片配额和置顶上限。
9. 当前文件路径直接承担逻辑资产和物理存储职责，未来接对象存储前需要增加存储抽象。
10. 多个重型任务并发时缺少统一的内存、FFmpeg、ASR 和下载并发预算。

## 5. 目标架构

```text
公共/企业热点线索池
  标题、摘要、URL、来源、时间、事件聚类、热度、媒体链接
                         │
                         ├── 用户从热点专题包开始
                         │
用户自由输入 ──→ 结构化选题简报
                         │
                         ↓
                  事实与媒体候选检索
                         │
             ┌───────────┴───────────┐
             ↓                       ↓
      热点事实与热点媒体        Buffalo 原本素材与品牌证据
             └───────────┬───────────┘
                         ↓
                   任务级证据包
              事实、素材、角色、来源、缺口
                         ↓
                 用户确认角度和证据
                         ↓
                 生成所选平台的内容
                         ↓
             质量门禁、预览、发布或归档
```

### 5.1 四类核心对象

#### 热点信号

保存外部世界发生了什么。只包含元数据和可追溯链接，不等同于可用于成片的媒体。

#### 选题简报

保存用户想写什么、写给谁、解决什么问题、使用什么时间范围和输出形式。

#### 任务级证据包

保存本次任务允许使用的事实、热点媒体、品牌证据和 Buffalo 素材片段，以及每项证据承担的内容职责。

#### 物理存储对象

保存文件位于本地磁盘还是对象存储、大小、指纹、保留类别、引用数、最后使用时间和清理状态。逻辑素材不得依赖“文件永远存在”。

## 6. 选题简报

### 6.1 字段

首版建议使用以下结构：

```json
{
  "id": "topic-brief-id",
  "raw_input": "我想写南非清关和末端配送风险",
  "subject": "南非物流",
  "audience": "刚进入南非市场的跨境卖家",
  "goal": "风险教育与线索获取",
  "angle": "从清关和末端配送两个节点说明进入南非市场前的准备",
  "locations": ["South Africa"],
  "logistics_nodes": ["customs", "last_mile"],
  "freshness_mode": "recent_or_evergreen",
  "time_window_days": 7,
  "platforms": ["xiaohongshu"],
  "content_form": "carousel",
  "must_include": [],
  "must_avoid": ["绝对时效保证", "百分百安全"],
  "created_by": 1,
  "status": "draft"
}
```

### 6.2 生成规则

- 用户输入已经明确包含受众、主题和目标时，优先使用确定性解析和已有分类词表，不强制调用模型。
- 输入过宽或含义不清时，最多调用一次低成本文本模型补全简报。
- 系统不得擅自增加具体业务承诺、客户案例和数字。
- 解析后必须向用户展示主题、受众、内容角度和时间范围。
- 用户可直接修改结构化字段，不要求重新输入整段话。

### 6.3 两种入口

#### 从自由输入开始

1. 用户输入需求。
2. 系统形成选题简报。
3. 检索近期热点和常青事实。
4. 返回 2～3 个有证据支持的角度。
5. 用户选择或修改角度。

#### 从热点专题包开始

1. 用户选择热点专题包。
2. 专题包事实自动进入候选证据。
3. 用户填写或选择希望连接的物流话题。
4. 系统匹配 Buffalo 原有素材和品牌证据。
5. 用户确认任务级证据包。

两个入口最终必须汇合到同一个选题简报和证据包，不维护两套生成链路。

## 7. 热点、原有素材和物流话题的关联

### 7.1 分镜职责

| 内容职责 | 默认来源 | 硬约束 |
| --- | --- | --- |
| `hotspot_hook` | 当前热点事实或已确认热点媒体 | 必须可追溯到当前事件 |
| `fact_context` | 官方来源、独立来源、信息卡 | 不得使用品牌素材冒充事件现场 |
| `impact_explainer` | 热点事实、结构化分析、信息卡 | 因果关系必须有依据或使用条件式表达 |
| `brand_proof` | Buffalo 原本素材和品牌证据 | 不得使用外部新闻画面证明 Buffalo 能力 |
| `brand_close` | Buffalo 原本素材 | 不得增加无证据的结果承诺 |

### 7.2 检索顺序

1. 按时间、地区、权利、文件状态和内容职责执行硬过滤。
2. 使用 FTS、结构化标签和实体词召回。
3. 从热点事实中最多保留 20 个候选。
4. 从热点媒体片段中最多保留 12 个候选。
5. 从 Buffalo 原有素材片段中最多保留 20 个候选。
6. 对候选执行规则重排或本地语义重排。
7. 每个内容职责最多展示 Top 3，并显示来源、时间范围、匹配原因和权利状态。

不得把整个热点池、完整文章、完整视频字幕或整个素材库直接发送给远程模型。

### 7.3 证据包确认

用户确认的不是“把素材永久放进某个库”，而是本次任务允许使用哪些证据：

- 事实是否入选；
- 事实承担什么论点；
- 媒体承担什么画面职责；
- Buffalo 素材证明什么实际动作；
- 哪些缺口必须补充；
- 哪些内容禁止生成。

同一素材可以被多个证据包引用；同一任务中不得复制物理文件。

## 8. 推荐与个性化

### 8.1 共享底池

所有用户看到同一事件事实、来源数量、发布时间和基础热度。翻译、聚类、转写和媒体分析结果在共享范围内按输入快照和处理版本缓存。

### 8.2 个性化视图

推荐排序可以根据以下个人信号变化：

- 用户选择过的物流节点；
- 收藏和忽略记录；
- 最近生成主题；
- 目标平台；
- 企业近期已发布内容；
- 当前原素材库可覆盖程度。

个性化只改变排序和默认筛选，不改变基础事实，不为不同用户生成互相矛盾的热点摘要。

### 8.3 防止信息茧房和重复

- 始终提供“查看全部共享热点”入口。
- 推荐卡显示推荐原因，例如“与你近期关注的清关主题相关”。
- 同类选题近期已发布时降低排序，并显示重复提醒。
- 用户仍可通过自由输入绕过推荐列表。

## 9. 质量门禁

### 9.1 选题门禁

- 主题、受众和内容目的至少明确两项。
- 宽泛输入先给角度，不直接生成全文。
- 需要时效性的内容必须设置时间窗口。
- 没有新事实时标记为常青内容。

### 9.2 事实门禁

- 每条具体事实必须绑定来源 URL、发布者和时间。
- 具体数字、政策变化、事故、时效和安全结论优先使用官方来源；没有官方来源时至少需要两个独立来源。
- 单一二级发现来源不得成为高风险事实的唯一依据。
- 事实过期、来源失效或不同来源冲突时进入人工复核。

### 9.3 品牌门禁

- Buffalo 时效、覆盖率、安全、客户结果和案例必须绑定已确认品牌证据。
- 自有画面只能证明画面中实际可见的动作。
- 品牌证据不足时，自动降级为流程说明或行业建议。

### 9.4 媒体门禁

- `link_only`、`unknown`、`red` 或处理失败的媒体不得进入发布成片。
- 热点事实镜头只允许使用当前事件或明确相关事件的媒体片段。
- Buffalo 品牌镜头只从原本素材库召回。
- 不为了满足片段数量使用弱相关画面。

### 9.5 输出门禁

输出状态分为：

- `angle_only`：只给角度，证据尚未确认；
- `internal_preview`：允许内部预览，显示事实、素材或权利缺口；
- `needs_review`：存在需要人工处理的问题；
- `publish_ready`：事实、品牌、媒体、版权和技术检查全部通过。

素材不足时优先缩短视频、改为图文或纯文本，不用无关素材补齐 60 秒。

## 10. 模型与 Token 成本控制

### 10.1 普通单平台任务预算

| 阶段 | 最大调用 | 输入上限 | 输出上限 |
| --- | ---: | ---: | ---: |
| 选题简报补全 | 0～1 | 2,000 | 500 |
| 内容规划 | 1 | 5,000 | 1,000 |
| 正式生成 | 1 | 5,000 | 1,500 |
| 合计 | 最多 3 | 最多 12,000 | 最多 3,000 |

如果确定性规则已经能形成简报，第一阶段不调用模型。

### 10.2 多平台规则

- 默认只生成用户当前选择的平台。
- 多平台共用同一选题简报和证据包。
- 平台格式转换优先使用确定性规则。
- 用户明确要求独立深度改写时，才为额外平台增加模型调用和独立预算。
- 不再默认一次生成小红书、抖音、Facebook、Twitter 和 Reddit 全部内容。

### 10.3 上下文压缩

送入模型的证据只包含：

- 3～5 条最终事实；
- 每条事实的短摘要、来源和时间；
- 6～10 个最终素材片段的描述、标签和时间范围；
- 已确认品牌证据；
- 禁止表达；
- 目标平台和输出结构。

完整网页、完整转写和原始模型分析结果留在本地，不进入最终生成上下文。

### 10.4 缓存

缓存键继续使用：

```text
输入快照哈希 + 模型角色 + 模型名称 + 提示词版本 + 输出结构版本
```

缓存命中不重复计费。以下变化必须使旧缓存失效：

- 原文快照变化；
- 用户修改选题角度；
- 证据包成员变化；
- 品牌证据状态变化；
- 提示词或输出结构版本变化。

### 10.5 重试

- 网络临时错误最多自动重试一次。
- 结构解析失败可以使用确定性修复，不立即重新请求模型。
- 质量门禁失败不自动循环生成。
- 用户修改证据或角度后视为新修订，但继续复用未变化的缓存。

## 11. 媒体与缓存生命周期

### 11.1 保留矩阵

| 数据类型 | 默认保留 | 清理条件 | 清理后保留 |
| --- | --- | --- | --- |
| 热点结构化事实 | 长期 | 不自动删除 | 全部结构化字段 |
| 热点原始抓取 payload | 90 天 | 已完成结构化且无审计保护 | 哈希、来源、结构化摘要 |
| 未确认媒体候选 | 30 天后归档 | 未确认、无项目引用 | URL、标题、来源、权利状态 |
| 已下载热点低清源文件 | 最后使用后 7 天 | 未置顶、无活动引用 | 指纹、转写、标签、来源、事件片段 |
| 缩略图和关键帧 | 7～30 天 | 可从源文件或链接重建 | 描述、标签和对象引用 |
| OCR、ASR 与转写文本 | 长期 | 仅按隐私或合规要求删除 | 处理版本和审计记录 |
| FFmpeg/下载临时文件 | 任务结束立即清理，最长 24 小时 | 不属于活动任务 | 错误摘要和任务记录 |
| 失败任务中间文件 | 24 小时 | 无人工保留 | 失败阶段和错误摘要 |
| 内部预览草稿 | 14 天 | 未置顶、无活动引用 | 脚本、证据包、质量报告 |
| 最终成片 | 30 天 | 未置顶、未进入保留期 | 任务、脚本、素材清单、哈希 |
| 已发布成片 | 发布后按策略迁移或删除本地副本 | 平台发布成功且无需本地回退 | 发布记录和输出哈希 |
| Buffalo 原本素材 | 长期 | 仅管理员主动处理 | 元数据和引用关系 |
| 模型响应缓存 | 30 天或达到容量上限 | TTL＋LRU | 调用审计与用量汇总 |
| 普通运行日志 | 14～30 天 | 日志轮转 | 关键告警与审计日志 |

### 11.2 引用感知垃圾回收

任何物理文件删除前必须检查：

1. 是否被活动视频任务引用；
2. 是否被待发布或定时发布任务引用；
3. 是否被当前项目修订引用；
4. 是否被内部预览回退期保护；
5. 是否被用户置顶；
6. 是否属于不可重建的 Buffalo 原始素材；
7. 路径是否位于允许的媒体根目录；
8. 删除操作是否能写入审计日志。

引用关系无法判断时按“正在引用”处理，禁止删除。

### 11.3 三种清理触发

- 任务终态清理：任务成功、失败或取消后立即清理临时文件。
- 每日生命周期清理：按保留期限、引用和置顶状态清理。
- 磁盘压力清理：达到容量水位时立即按 LRU 和文件大小回收可重建缓存。

每日凌晨清理只能作为兜底，不能代替任务结束时清理和容量压力清理。

### 11.4 淘汰顺序

磁盘不足时按以下顺序处理：

1. 失败任务和孤儿临时文件；
2. 未被使用的下载缓存；
3. 可重建关键帧、缩略图和低清预览；
4. 最久未使用的热点低清源文件；
5. 过期内部草稿；
6. 过期未置顶成片；
7. 模型响应缓存中的最久未访问项。

不得自动删除 Buffalo 原始素材和置顶文件。

## 12. 云端存储架构

### 12.1 第一阶段：单服务器

继续使用当前本地文件存储，但必须：

- 将永久素材、热点缓存、成片、临时文件放入独立目录；
- 每类目录设置容量预算；
- 开启实际生命周期清理；
- 增加任务容量预估和预留；
- 对临时目录执行孤儿文件扫描；
- 对模型缓存和日志设置大小上限。

### 12.2 第二阶段：存储抽象

增加统一存储接口：

```text
put(stream, retention_class)
open(object_id)
exists(object_id)
delete(object_id)
touch(object_id)
signed_url(object_id)
```

本地文件系统和 S3 兼容对象存储分别实现该接口。业务表只保存稳定对象 ID，不直接假设文件位于 `static/assets`。

### 12.3 第三阶段：对象存储

- Buffalo 原始素材、置顶成片和需要长期保留的发布文件进入对象存储。
- 云服务器本地只保存最近使用的低清缓存和计算临时文件。
- 对象存储设置版本、生命周期和企业配额。
- 已从本地淘汰的文件按需下载到本地缓存。
- 原始链接失效但企业要求长期保留的热点媒体，必须在权利允许的前提下转为企业保留对象。

### 12.4 内容寻址与去重

- 文件使用 SHA256 作为去重依据。
- 同一企业内相同文件只保存一个物理对象。
- 不同项目、用户和证据包只增加引用。
- 第一阶段不对不同企业的私有素材做跨企业物理去重，避免权限和隐私复杂度。
- 明确公共领域或开放许可媒体可在未来单独进入平台级公共对象池。


### 13.2 100 GB 单服务器参考分配

| 用途 | 参考预算 |
| --- | ---: |
| 系统、数据库、日志和固定安全余量 | 20 GB |
| Buffalo 原本素材 | 40 GB |
| 热点媒体缓存 | 20 GB |
| 成片与草稿 | 10 GB |
| FFmpeg、下载和分析临时空间 | 10 GB |

该分配是初始配置，不是硬编码。任何一类需要扩大时，都必须明确压缩其他类别或增加存储。

### 13.3 生成前估算

每个任务启动前计算：

```text
预计峰值空间 =
待下载源文件上限
+ 转码临时空间
+ 音频、字幕和关键帧
+ 预览与最终输出
+ 安全系数
```

准入条件：

```text
当前可用空间
- 已被运行中任务预留的空间
- 当前任务预计峰值空间
>= 固定安全余量
```

不满足条件时任务不进入执行队列，只保留选题简报和证据包。

### 13.4 水位行为

- 剩余空间高于 30%：正常运行。
- 低于 30%：立即执行可重建缓存回收。
- 低于 20%：暂停自动热点媒体准备和非必要高清渲染。
- 低于 10%：停止新的下载、视觉分析、TTS 和视频生成；浏览、编辑、元数据操作继续可用。
- 固定安全余量与百分比同时生效，取更严格者。

现有 15% 告警和 5% 停止阈值应在实施时迁移到上述分级水位，避免单个重型任务耗尽最后空间。

### 13.5 置顶与永久保留

- 置顶文件仍计入企业或用户配额。
- 达到配额后禁止继续置顶或上传，不静默删除现有置顶文件。
- 管理员可以查看每个置顶文件占用空间、最后访问时间和引用项目。
- 用户取消置顶后，文件重新进入对应生命周期。

## 14. 内存和并发治理

磁盘问题来自长期累积，内存问题主要来自并发和无界缓存。4 核 8 GB 基础服务器建议：

- 同时最多运行 1 个视频转码或视觉重分析重型任务；
- 同时最多运行 1 个素材分析任务；
- 同时最多运行 2 个流式下载；
- 视频上传和下载必须使用固定大小数据块，禁止整文件读入内存；
- FFmpeg、ASR 和视觉处理通过任务队列执行，HTTP 请求不直接无限启动子进程；
- ASR 或本地模型每个 Worker 最多加载一份；
- 内存缓存使用有字节上限的 LRU；
- 任务取消时终止整个子进程组；
- Worker 达到任务数或内存阈值后平滑回收；
- 记录任务峰值 RSS、处理时长、输入文件大小和退出原因。

未来扩展多个 Worker 时，调度器必须使用共享租约或独立队列。SQLite 单机阶段继续保持单应用 Worker，避免重复调度和写冲突。

- 热点入口不会覆盖用户自定义物流话题。

### 19.2 证据测试

- 热点事实只绑定热点来源。
- 品牌证明只召回 Buffalo 原素材和品牌证据。
- 同一证据包不复制物理文件。
- 权利未知或红色媒体不能进入发布成片。
- 证据不足时阻止 `publish_ready`。
- 素材不足时允许切换图文或缩短视频。

### 19.3 成本测试

- 普通任务不超过 3 次调用。
- 输入、输出 Token 超限时在调用前阻止。
- 相同快照和提示词版本命中缓存。
- 证据包变化后旧缓存失效。
- 只选择一个平台时不生成其他平台内容。
- 网络失败不会无限重试。

### 19.4 生命周期测试

- 活动任务、置顶、原本素材和不安全路径永不删除。
- 临时文件在任务终态或 24 小时后清理。
- 热点低清源文件按最后使用时间清理。
- 文件删除后元数据、来源、转写和证据引用仍存在。
- 清理重复执行幂等。
- 孤儿文件可以识别并进入预览。
- 模型缓存按 TTL 和容量上限淘汰。

### 19.5 容量与并发测试

- 任务启动前会扣除运行中预留。
- 预计峰值超过安全余量时返回明确错误，不启动子进程。
- 达到 30%、20%、10% 水位时执行对应行为。
- 同时提交多个重型任务时只运行允许数量。
- 取消任务后释放内存、进程和存储预留。
- FFmpeg 异常退出不会遗留永久临时文件。

### 19.6 对象存储测试

- 本地和对象存储实现具有相同接口行为。
- 对象被本地淘汰后可以重新拉取。
- 私有对象 URL 有效期受限。
- 对象存储不可用时不丢任务元数据。
- 不同企业不能读取彼此私有对象。

## 20. 验收标准

### 20.1 产品验收

1. 用户可以完全不使用固定话题选择器，直接输入自定义物流话题。
2. 系统先显示结构化选题和证据覆盖，再生成内容。
3. 热点专题包可以关联用户自定义物流主题。
4. 同一热点基础事实对所有用户一致，个人推荐排序和草稿不同。
5. 用户只确认任务证据，不需要手工维护整个热点素材库。
6. 没有热点时可以生成常青内容，但不会伪装为最新热点。

### 20.2 质量验收

1. 每条事实可追溯到来源、发布者和时间。
2. 每条 Buffalo 能力表达有品牌证据或实际素材支持。
3. 热点镜头和品牌镜头不会跨职责混用。
4. 权利不允许的媒体不能进入发布级输出。
5. 弱相关素材不会为了补时长强行进入成片。
6. 证据不足时系统给出缺口和降级格式。

### 20.3 成本验收

1. 普通单平台任务最多 3 次远程调用。
2. 默认总输入不超过 12K Token，总输出不超过 3K Token。
3. 热点采集、热度、来源统计和下载状态不调用文本模型。
4. 相同证据快照可以命中缓存。
5. 系统不默认生成用户未选择的平台。

### 20.4 存储验收

1. 未选择热点不会自动产生大文件。
2. 所有大文件都有保留类别、最后使用时间、引用状态和清理策略。
3. 临时文件、热点缓存、草稿、成片、模型缓存和日志均有容量上限。
4. 清理文件后业务记录和审计链仍存在。
5. 达到磁盘水位时系统能回收、降级和停止重型任务。
6. 置顶和永久素材计入配额，不能无限绕过清理。
7. 单个任务在启动前完成峰值容量估算和空间预留。

### 20.5 内存验收

1. 4 核 8 GB 服务器默认只运行一个视频重型任务。
2. 视频上传、下载和对象存储传输全程流式。
3. 任务取消或失败后无孤儿 FFmpeg/ASR 子进程。
4. 内存缓存有字节上限，Worker 可以安全回收。

## 21. 上线顺序与回退

1. 先上线选题简报，只记录不改变旧生成结果。
2. 再上线证据包，由管理员或测试账户试用。
3. 启用新质量状态，但先保持发布级输出人工确认。
4. 收紧模型预算和默认平台数量。
5. 运行完整生命周期 dry-run 至少 7 天，核对所有候选和引用保护。
6. 审批后启用实际清理。
7. 启用容量准入、配额和水位降级。
8. 数据量达到触发条件后再迁移对象存储。

每个阶段必须有独立功能开关。出现异常时可以回到旧读取链路，但不得关闭事实、版权和磁盘硬门禁。

## 22. 非目标

- 不建设自治多 Agent 系统。
- 不把整个互联网抓取为本地素材库。
- 不批量下载 TikTok、X、Instagram、YouTube 等版权不明确媒体。
- 不用大模型替代确定性热度计算、引用检查和容量计算。
- 不在第一阶段引入 PostgreSQL、Redis、Celery、MinIO 等整套基础设施。
- 不承诺所有内容完全无人审核即可发布。
- 不通过无限增加 Token 或模型重试掩盖事实和素材缺口。

## 23. 开发执行清单

按以下顺序拆任务，不并行跨越硬依赖：

- [ ] 建立现有成本、磁盘、临时空间和峰值内存基线。
- [ ] 增加选题简报数据结构、接口和前端确认。
- [ ] 让热点视频规划器优先使用自定义选题。
- [ ] 增加任务级证据项和双库职责绑定。
- [ ] 增加事实、品牌、媒体和输出质量状态。
- [ ] 默认改为只生成用户选择的平台。
- [ ] 将普通任务预算收紧到 3 次调用、12K 输入、3K 输出。
- [ ] 补齐临时文件、失败任务、关键帧、模型缓存和日志生命周期。
- [ ] 增加企业、热点缓存和用户输出配额。
- [ ] 增加任务空间估算、预留和释放。
- [ ] 增加 30%/20%/10% 磁盘水位行为。
- [ ] 增加重型任务、素材分析和下载并发限制。
- [ ] 连续运行 7 天 dry-run 并完成清理候选人工核对。
- [ ] 审批后启用实际清理并验证审计、幂等和异常恢复。
- [ ] 达到对象存储触发条件后再实施存储抽象和迁移。

完成以上清单后，系统应形成“自由选题 → 证据检索 → 双库匹配 → 有界生成 → 质量门禁 → 生命周期回收”的闭环。
