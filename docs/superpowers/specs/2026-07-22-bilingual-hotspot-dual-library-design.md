# 双语热点与双素材库成片设计

## 1. 背景与目标

当前热点工作台已经可以从最多五个可信源读取南非热点，并将开放许可图片保存为本地素材，但仍有三个缺口：

1. 热点只显示英文原文，中文使用者理解和选题效率较低。
2. 原站图片候选、开放许可补充图和公司自有素材的入口与状态不够清楚。
3. 视频匹配把“热点事实画面”和“Buffalo 品牌证明画面”视为同一类候选，容易造成画面不相关或证据角色混淆。

本次设计的目标是：

- 热点永久保留英文原文，同时提供缓存后的中文译文。
- 内容资产明确分成“原本素材库”和“热点素材库”。
- 允许下载热点媒体候选，但在进入宣传成片前执行人工权利确认。
- 在分镜层组合两个库，而不是在资产层混库或复制文件。
- 默认以热点素材 30%、公司自有素材 70% 形成兼具时效性与品牌真实性的样本。
- 不引入向量数据库、多 Agent 编排或新的模型供应商。

## 2. 已确认的产品边界

### 2.1 双语热点

- 英文标题和摘要是来源原文，不允许被中文翻译覆盖。
- 中文标题和摘要在用户第一次选择热点时生成，成功后写入数据库缓存。
- 同一份原文快照未变化时直接复用中文译文，不重复调用模型。
- 原文快照变化后将译文标记为过期，下一次选择时重新翻译。
- 翻译失败不影响热点使用；页面继续显示英文，并提供“重试翻译”。
- 翻译只服务内部理解，事实核验仍以英文原文与官方来源为准。

### 2.2 两个素材库

#### 原本素材库

- 保存 Buffalo 公司自有或已经取得明确授权的图片和视频。
- 可长期复用，可用于品牌能力、仓储流程、分拣、扫描、装车和人员作业等分镜。
- 原有文件路径和数据不迁移，避免破坏现有视频链路。

#### 热点素材库

- 按热点保存新闻原站图片、原站视频链接、已授权视频文件、开放许可补充图及对应来源信息。
- 每条素材必须记录热点 ID、媒体来源、原始 URL、落地 URL、抓取时间、文件指纹、作者或媒体名称、权利状态和人工确认人。
- 热点素材只证明事件背景或提供视觉语境，不能直接证明 Buffalo 的服务能力或具体履约结果。

### 2.3 热点视频边界

热点视频采用“先发现链接、后确认权利、再下载分析”的三段式流程，不能因为页面可以播放就自动下载或进入成片。

- 自动发现范围：新闻页中的 `og:video`、`video/source`、JSON-LD `VideoObject.contentUrl`、`VideoObject.embedUrl`，以及页面内嵌的 YouTube 单条视频链接。
- 人工补充范围：管理员可把单条 YouTube、TikTok 或新闻视频 HTTPS 链接绑定到指定热点。频道首页和播放列表不能直接作为成片素材。
- 视频平台链接默认只保存标题、作者、发布时间、缩略图、落地页和平台 ID，不携带 Cookie，不绕过登录、地区限制、付费墙或 DRM。
- 管理员点击“确认并下载到库”后，候选自动记录为已确认 `yellow` 并进入下载分析；`red` 视频仍只保留链接与元数据。
- 下载成功后统一转为现有素材处理链路可识别的 MP4，使用 ffprobe 检查时长、分辨率、画幅、编码和音轨，再由现有视频分段与语义分析生成可匹配时间段。
- 热点视频在时间线中只使用与热点事实相关的短片段；默认单段 1～4 秒，不整段搬运新闻视频，也不把不同时间地点的画面伪装成同一事件现场。
- YouTube 频道发现作为独立、可降级的采集器：只拉取三个已确认频道最近的单视频元数据并进入热点候选，不自动下载；任一频道失败不影响官方新闻抓取和双库成片主链路。

### 2.4 权利状态

热点媒体候选分为三档：

- `green`：开放许可、公共领域、公司已取得授权或来源明确允许转载。可以直接进入样本，但仍显示来源与署名。
- `yellow`：权利状态未知，只保存链接、公开元数据和缩略图。管理员点击“确认并下载到库”即完成本地内部使用确认，系统自动记录确认人、确认时间、原始页面和发布方并开始下载分析，不再要求连续填写权利状态、许可证、署名和证据链接。
- `red`：来源明确禁止转载、属于付费图库、受平台下载限制或人工判定不应使用。只保存链接和元数据，不进入成片。

“下载到本地”与“允许进入成片”是两个独立状态。系统不得因为文件已经下载就自动将其视为公司资产或可发布素材。

参考边界：

- 中国国家版权局明确指出，以新闻事件为主题的摄影作品仍受著作权保护，公众号与非媒体机构使用他人摄影作品原则上应取得许可。
- 中国《著作权法》第二十四条的新闻报道例外要求使用属于不可避免的引用，注明作者或作品信息，并且不得影响作品正常使用或不合理损害权利人权益。
- 南非《Copyright Act 98 of 1978》同样保护摄影作品；有关 current events 的 fair dealing 不能解释为所有新闻图片均可无条件复制用于公司宣传。

本设计是产品风险控制规则，不替代针对具体素材的法律意见。

## 3. 采用的方案

### 3.1 方案比较

#### 方案 A：两个素材库统一混合检索

实现最简单，但新闻画面可能被错误用于品牌证明，公司仓库画面也可能被当成热点现场，事实角色和版权角色容易污染。因此不采用。

#### 方案 B：先判断分镜职责，再进入对应素材库匹配

每个分镜先标记为热点事实、影响解释、品牌证明或行动收尾，再按职责选择素材库和排序规则。质量、成本和可解释性最平衡，因此采用。

#### 方案 C：完全人工选镜头

质量可控，但无法在周五样本交付节奏下稳定复用，也无法发挥现有语义分析结果。因此只保留人工复核，不作为主要流程。

## 4. 页面结构

### 4.1 内容资产页

页面顶部使用两个一级标签：

1. `原本素材库`
2. `热点素材库`

原本素材库延续现有图片、视频、分类、语义分析和桌面接入能力。

热点素材库使用“热点分组 + 媒体候选”结构：

- 左侧或顶部筛选：热点、来源、媒体类型和抓取时间。
- 卡片显示缩略图、所属热点的中英文标题、媒体来源、处理状态和是否已用于样本。
- 尚未下载的图片或单视频候选只提供一个一级动作“确认并下载到库”；点击后按钮立即进入禁用/下载中状态，防止重复提交。
- 红色素材不显示下载或加入成片操作，只提供“打开原始来源”。
- 视频卡片额外显示时长、画幅、处理状态和可用片段数量；未下载的视频显示平台缩略图和“仅链接”。
- 已下载视频可预览，但页面只允许选择经过语义分析的具体时间段，不能默认把整段视频加入时间线。
- 允许从热点工作台直接跳转到当前热点对应的素材分组。

### 4.2 热点工作台

热点列表优先显示中文标题，下一行保留英文原文；摘要区域以中文为主，英文原文可展开。

在“检查素材”步骤增加：

- 当前热点已经发现的图片和视频候选数量。
- 绿色、黄色、红色素材数量。
- “查看热点素材”入口。
- 每个分镜的素材库来源标识：`热点库` 或 `原本库`。
- 每个分镜的 Top 3 候选和匹配依据。
- “添加视频链接”入口，把单条 YouTube、TikTok 或新闻视频链接绑定到当前热点；频道链接需要先选择其中一条具体视频。

## 5. 双库成片规则

### 5.1 分镜职责

每个视频分镜必须属于下列一种职责：

| 分镜职责 | 默认素材库 | 用途 |
| --- | --- | --- |
| `hotspot_hook` | 热点素材库 | 建立“现在发生了什么”的注意力 |
| `fact_context` | 热点素材库 | 展示官方事实、地点或事件背景 |
| `impact_explainer` | 信息卡或热点素材库 | 解释对卖家、运输或仓储可能产生的影响 |
| `brand_proof` | 原本素材库 | 展示 Buffalo 实际仓储、扫描、分拣和装车能力 |
| `brand_close` | 原本素材库 | 品牌收尾与行动建议 |

`brand_proof` 和 `brand_close` 禁止使用来源不明的热点媒体证明品牌能力。

### 5.2 默认时间线

30–35 秒视频默认结构：

1. 0–4 秒：热点钩子，使用绿色或已确认黄色热点素材。
2. 4–8 秒：双语标题卡、官方来源和发布时间。
3. 8–13 秒：影响解释，使用热点补充图或信息卡。
4. 13–25 秒：Buffalo 自有仓储、扫描、分拣、装车实拍。
5. 25–32 秒：公司自有品牌收尾画面。

热点素材约占 30%，原本素材约占 70%。比例是排序偏好而非强制帧数；如果没有合规且相关的热点画面，使用双语标题卡替代，不强行填充无关图片。

### 5.3 候选召回与排序

系统先执行硬过滤，再执行排序：

硬过滤规则：

- 热点事实分镜只从当前热点及相关主题的热点素材中取候选。
- 品牌证明分镜只从原本素材库取候选。
- `red` 热点素材不得进入候选。
- `yellow` 热点素材未人工确认前只能预览，不能被应用到时间线。
- 不使用缺失文件、处理失败或无法读取的素材。
- `video_link` 只有链接和缩略图，不能进入时间线；必须先素材化为 `video_file` 并完成分段分析。
- 热点视频候选的片段时间必须落在实际时长内，且不得超过单个分镜目标时长两秒以上。

排序因素：

- 语义相关度：40%。
- 主体与动作匹配：25%。
- 来源可信度或公司所有权：15%。
- 清晰度、方向与画幅适配：10%。
- 与相邻镜头的视觉差异：10%。

每个分镜最多返回 Top 3。页面必须显示素材库来源、分数、时间范围、权利状态和匹配原因。

图片候选以整张图参与排序；视频候选以 `asset_segment` 为单位参与排序。同一热点视频可以产生多个片段，但同一次 Top 3 中最多出现一个片段，避免三个结果实际来自同一条新闻视频。

### 5.4 多样性控制

- 同一素材不得连续用于两个分镜。
- 同一视频的相邻时间段不得伪装成不同地点或不同事件。
- 连续两条样本尽量避免完全相同的热点图和品牌镜头组合。
- 优先轮换仓库全景、人物操作、设备特写、扫描、分拣、装车和车辆等镜头类型。

## 6. 数据与接口

### 6.1 热点双语字段

在热点记录中增加：

- `title_zh`
- `summary_zh`
- `translation_status`
- `translation_snapshot_sha256`
- `translated_at`
- `translation_model`

增加接口：

- `POST /api/hotspots/{id}/translate`：按需翻译并缓存。

### 6.2 热点媒体候选

新增独立的热点媒体记录，不把黄色或红色候选提前写入正式 `assets`：

- `id`
- `hotspot_id`
- `media_kind`
- `platform`
- `platform_media_id`
- `source_page_url`
- `original_media_url`
- `embed_url`
- `thumbnail_url`
- `local_path`
- `publisher`
- `author`
- `published_at`
- `mime_type`
- `duration_seconds`
- `width`
- `height`
- `rights_tier`
- `rights_note`
- `license_name`
- `rights_evidence_url`
- `attribution`
- `download_status`
- `processing_status`
- `error_message`
- `sha256`
- `asset_id`
- `confirmed_by`
- `confirmed_at`
- `created_at`

`media_kind` 只允许：

- `image`：图片候选或已下载图片。
- `video_link`：只保存外部视频链接与缩略图，不能直接匹配时间线。
- `video_file`：已授权下载且完成基础校验的视频文件，可在分析完成后按片段参与匹配。

状态流转固定为：

`discovered → metadata_ready → downloaded → processing → ready`

失败状态为 `download_failed` 或 `processing_failed`，允许管理员单项重试。权利状态与下载、处理状态彼此独立。

增加接口：

- `GET /api/hotspot-media`：按热点、类型和权利状态筛选。
- `POST /api/hotspots/{id}/media/discover`：读取当前原文中的图片与视频链接，生成候选。
- `POST /api/hotspots/{id}/media/attach`：人工绑定一条单视频 HTTPS 链接并读取公开元数据。
- `POST /api/hotspot-media/{id}/download`：仅对绿色或已确认黄色候选下载文件并计算指纹；未确认黄色和红色返回权利门禁错误。
- `PUT /api/hotspot-media/{id}/rights`：管理员确认 `green`、`yellow` 或 `red` 以及使用边界。
- `POST /api/hotspot-media/{id}/materialize`：将绿色或已确认黄色媒体登记为可匹配素材，但保留热点库归属和来源链。

抓取媒体时限制文件大小、MIME 类型、跳转域名和请求超时，并拒绝内网地址，沿用现有 SSRF 防护。

视频下载额外限制：单文件不超过现有 `MAX_VIDEO`，时长不超过 10 分钟；`yt-dlp` 使用 `noplaylist`、无 Cookie、无浏览器会话模式。下载后若 ffprobe 无法读取、没有视频流或文件超限，立即标记失败并删除临时文件，不登记为正式素材。

### 6.3 双库匹配输出

每个分镜匹配结果统一增加：

- `library_origin`：`owned` 或 `hotspot`。
- `hotspot_id`：热点片段必填，自有素材为空。
- `media_kind`：`image` 或 `video_file`。
- `segment_id`、`start_ms`、`end_ms`：视频片段必填，图片为空。
- `rights_tier`、`attribution`、`source_page_url`。
- `score` 与 `reasons`。

30/70 比例在时间线职责层实现：热点职责默认占前 30%，品牌职责默认占后 70%；不是把两个库的候选统一混排后再计算比例。

## 7. 模型与成本策略

- 热点抓取和媒体发现不调用文本模型。
- 中文翻译只在首次选择热点时调用一次 `planner_text`，使用独立 prompt 版本和缓存键。
- 双库分镜职责优先由固定模板确定，不为每个分镜额外调用模型。
- 素材候选沿用本地语义分析与规则排序；只有现有描述不足时才考虑已配置的可切换模型。
- 单个热点翻译预算最多一次调用；失败不自动循环重试。
- 视频元数据、ffprobe、抽帧、分段和本地语义排序不调用大模型；只有现有素材描述不足且管理员明确触发重新分析时，才沿用当前可切换多模态模型。

## 8. 错误与降级

- 翻译失败：保留英文，显示“中文翻译失败，点击重试”。
- 图片发现失败：热点仍可用于事实选题，使用双语标题卡替代。
- 下载失败：保留候选 URL 和失败原因，允许单项重试。
- 平台只返回 HLS、需要登录、存在 DRM 或 `yt-dlp` 不支持：保留 `video_link`，标记不可下载，不阻塞热点选题。
- 视频下载成功但处理失败：不进入匹配，保留来源和错误原因，允许重新处理。
- 视频没有高相关片段：使用热点图片或双语标题卡，不因存在视频文件就强制使用。
- 版权信息缺失：归入黄色，不自动进入成片。
- 原站明确禁止或平台下载失败：归入红色，只保留链接。
- 热点素材不足：不降低品牌素材门槛，自动提高原本素材占比。
- 原本素材匹配不足：阻止 MP4 成片，提示补充对应动作、主体或场景素材。

## 9. 测试与验收

### 9.1 自动化测试

- 原文写入后不丢失，中文翻译可缓存、可失效、可重试。
- 原文快照未变化时不会重复产生模型调用。
- 媒体候选正确保存来源、文件指纹与权利状态。
- 新闻页能发现 `og:video`、HTML5 视频、JSON-LD VideoObject 和 YouTube 嵌入链接，并按规范化 URL 去重。
- YouTube/TikTok 单视频可绑定热点；频道页和播放列表不能直接进入下载任务。
- 黄色素材未确认前不能进入时间线；红色素材始终不能进入时间线。
- `video_link` 不能进入时间线；已授权视频完成下载和分段后以具体时间范围参与 Top 3。
- 品牌证明分镜不会返回热点素材。
- 热点事实分镜优先返回当前热点的媒体。
- 无热点图片时生成标题卡，不中断样本生成。
- Top 3 候选包含库来源、权利状态、分数和匹配依据。
- 同一热点视频的多个片段不会占满同一分镜的 Top 3。

### 9.2 浏览器验收

1. 热点列表同时显示中文标题和英文原文。
2. 选择未翻译热点时只产生一次翻译请求；刷新后直接恢复中文结果。
3. 内容资产页能在“原本素材库”和“热点素材库”之间切换。
4. 热点素材库能按热点、图片/视频和权利状态筛选。
5. 黄色素材确认前不能应用；确认后显示署名并可作为热点分镜候选。
6. 生成样本后，热点钩子来自热点库，品牌证明来自原本素材库。
7. 候选不足时页面明确说明使用标题卡或需要补素材，不伪造高质量结果。
8. 为一个热点绑定已授权的单条视频，完成下载和分析后，热点钩子的 Top 3 至少出现一个带起止时间的视频候选。
9. 未授权视频可预览来源和缩略图，但下载、应用到时间线按钮保持禁用。

## 10. 非目标

- 不自动绕过网站登录、付费墙、反爬或平台下载限制。
- 不把所有下载文件自动视为可发布资产。
- 不复制或迁移现有原本素材文件。
- 不建设新的向量数据库、多 Agent 系统或媒体版权判定模型。
- 不在本阶段直接发布到社交平台。
- 不下载整个 YouTube 频道或播放列表；三个已确认频道只在六小时热点任务中各读取最近 3 条公开单视频元数据，具体视频仍作为单条黄色候选进入权利门禁。

## 11. 媒体采集补齐（2026-07-22）

### 11.1 正文图片发现

媒体发现除 `og:image` 外，增加 `article`、`main`、`.entry-content`、`.post-content` 和常见正文容器内的普通图片。只接受公开 HTTPS 图片，按规范化 URL 去重，每篇最多保留 12 张；过滤 `logo`、`icon`、`avatar`、`banner`、`advert`、`tracking`、页头、页尾、侧栏和社交分享图片。图片没有明确许可时仍是黄色候选，不因出现在政府网站就自动视为可发布。

### 11.2 热点图片素材化

热点图片与视频使用同一个“确认并下载到库”动作。管理员点击后，系统自动记录确认人、确认时间、发布方和原始页面；图片限制响应体不超过 10MB，MIME 仅允许 JPEG、PNG、WebP。下载后复用 `media_assets.ingest_file`、来源链写入和现有图片语义分析，成功后变为 `ready` 并参与当前热点分镜匹配。已有 `red` 候选仍不能下载。

### 11.3 YouTube 视频热点发现

固定接入 `SA Today`、`South Africa Now`、`SABC Digital News` 三个频道。使用本机 `yt-dlp --flat-playlist` 只读取每个频道最近 3 条公开单视频的 ID、标题、发布时间、时长与缩略图，不下载文件、不读取 Cookie。每条视频同时创建一条视频热点和一个 `video_link` 黄色候选；管理员在卡片点击“确认并下载到库”后才下载该单条视频。单频道失败只写入信源健康状态，不影响官方 RSS 热点。

### 11.4 生成前素材检查

样本生成仍可产出脚本、图文和公众号内容，但视频对象必须带 `material_status` 和 `material_gaps`。当前热点没有 `ready` 图片或视频片段时，视频状态为 `blocked`，明确提示先下载并分析热点素材；只有热点职责与品牌职责都存在可匹配候选时才标记 `ready`。前端不得把 `blocked` 视频显示为可成片。

### 11.5 热点内容形态标识

热点选题列表必须根据当前热点已经登记的媒体候选显示内容形态，而不是让用户从来源名称猜测。存在 `video_link` 或 `video_file` 时显示“视频”；不存在视频但存在 `image` 时显示“图片”；两类候选都不存在时显示“纯文本”。视频热点即使同时带缩略图，也只归入“视频”，避免重复分类。

列表提供“全部形式、视频、图片、纯文本”筛选。标签与筛选都使用明确文字，不能只靠颜色表达；右侧当前选题标题旁同步显示同一标签。候选数据加载失败时降级为“纯文本”，不阻塞热点事实浏览和右侧四步流程。

### 11.6 单次确认下载（2026-07-23）

热点素材页不再弹出 `green / yellow / red`、使用边界、许可证、署名或证据链接输入框，也不再显示权利状态筛选。管理员点击“确认并下载到库”本身构成一次明确确认；后端必须在同一请求中先写入确认记录，再提交现有素材化任务。自动记录使用 `yellow`，`rights_note` 明确为内部热点素材确认，`attribution` 取发布方或作者，`rights_evidence_url` 取原始页面；不得伪造许可证名称。确认失败、来源 URL 无效或下载提交失败时显示明确错误，按钮恢复可用。已有 `red` 候选继续阻断。

### 11.7 外部图片可用性与来源回退（2026-07-23）

热点图片卡片的“查看原文”必须打开 `source_page_url`，只有缺少文章来源页时才回退到 `original_media_url`，不能再把图片文件直链冒充为原文。预览图加载失败时隐藏浏览器破图图标，改为显示“预览暂不可用”，并保留文章来源与重新检查入口。

正文图片发现优先读取 WordPress 的 `data-orig-file`，其次从 `srcset` 选择最大宽度候选，最后才使用 `data-lazy-src`、`data-src` 或 `src`。管理员显式执行“检查原文媒体”时，后端对图片候选执行低成本可用性检查：只接受返回 2xx 且 MIME 为 JPEG、PNG 或 WebP 的公开 HTTPS 地址；超时、502、非图片响应和内网跳转不写入新候选。视频候选不受图片检查影响。

已存在但外部图片暂时不可用的候选不自动删除，以免破坏已经确认或素材化的来源链；页面以失败占位呈现。图片成功素材化后，卡片预览优先使用素材库中的本地缩略图，避免继续依赖外站热链。系统不绕过来源站代理、登录、地区限制或反爬机制，也不在页面加载时批量请求外站。
