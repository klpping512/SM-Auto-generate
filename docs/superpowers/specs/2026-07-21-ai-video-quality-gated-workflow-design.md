# AI 对话到高质量视频生成联动设计

## 1. 目标

将当前彼此割裂的“AI 对话、内容编辑器、视频精准匹配、视频渲染”重构为一条以视频项目为中心、可恢复、可取消、带质量门禁的完整链路：

```text
AI 对话提出需求
→ 创建视频项目
→ 生成脚本与分镜
→ 匹配真实素材
→ 自动质量检查
→ 必要时只复核问题镜头
→ 生成低清预览
→ 正式渲染
→ 返回可播放、可下载、可发布的 MP4
```

默认体验是“一键启动”，不是“无条件一键完成”。只有通过质量门禁的项目才能自动生成正式成片；质量不足时，系统停在明确的问题节点并给出可执行的修正选项。

## 2. 第一性原理

### 2.1 用户目标是获得成片，不是搬运页面状态

用户的核心对象应是“一个视频项目”，而不是 AI 对话页、内容编辑器页或精准匹配页各自保存的一份临时数据。页面只负责展示和编辑同一个服务端项目，不再用 `localStorage` 作为生成状态的事实来源。

### 2.2 一键操作必须对应可观察的长期任务

生成视频包含脚本生成、素材匹配、TTS、FFmpeg 渲染和质量检查，时间远大于一次普通 HTTP 请求。任务必须持久化到数据库，具有唯一 ID、阶段、进度、心跳、取消状态、错误和产物。关闭页面、刷新或切换模块不能改变任务本身。

### 2.3 自动化不能掩盖质量不足

素材不足、语义证据不足、横屏裁竖屏风险或版权不明时，系统必须明确阻止正式渲染或请求局部复核，不能为了完成流程而选择无关镜头。

### 2.4 取消必须终止真实计算

“取消生成”不能只修改界面或数据库文字。系统必须停止排队任务、终止当前 TTS/FFmpeg 子进程、清理未完成临时文件，并保留已经完成且可复用的阶段产物。

## 3. 方案选择

### 方案 A：无条件一键成片

优点是操作最少；缺点是现有素材理解不足时会稳定地产生低质量结果，且问题只会在最终视频中暴露。拒绝采用。

### 方案 B：每一步强制人工确认

优点是风险可控；缺点是所有项目都必须经过脚本、素材、音色、字幕和预览确认，操作成本高。仅作为“严格审核模式”，不作为默认流程。

### 方案 C：自适应质量门禁

默认自动执行全部阶段。硬性门禁失败时停止；软质量分不足时只展示问题场景供用户替换或确认；通过后继续生成。该方案兼顾效率和成片质量，作为正式方案。

## 4. 统一领域模型

### 4.1 视频项目 `video_projects`

每次从 AI 对话发起视频生成时创建一个视频项目，至少保存：

- `id`：稳定项目 ID。
- `created_by`：创建人。
- `source_type`：`chat`、`editor` 或 `retry`。
- `source_snapshot`：用户指令、相关对话和事实来源的不可变快照。
- `title`、`platform`、`target_duration_ms`、`target_orientation`。
- `status`：项目总体状态。
- `current_revision_id`：当前脚本/分镜版本。
- `active_job_id`：当前生成任务。
- `created_at`、`updated_at`。

### 4.2 项目修订 `video_project_revisions`

脚本、分镜、镜头选择、字幕文本、音色和质量报告属于一次修订。重新生成或人工修改产生新修订，旧修订保留用于比较和回退，不在原 JSON 上无痕覆盖。

### 4.3 生成任务 `video_generation_jobs`

任务持久化保存：

- `id`、`project_id`、`revision_id`、`created_by`。
- `status`：`pending`、`running`、`needs_review`、`cancel_requested`、`canceled`、`failed`、`succeeded`。
- `stage`：当前流水线阶段。
- `progress`：0–100。
- `idempotency_key`：防止重复点击产生重复任务。
- `lease_owner`、`lease_expires_at`、`heartbeat_at`：防止多个本地服务同时执行同一任务。
- `cancel_requested_at`、`canceled_at`。
- `error_code`、`error_message`。
- `preview_path`、`output_path`、`quality_report`。

### 4.4 任务事件 `video_generation_events`

记录每次阶段切换、进度、警告、取消和失败。全站任务中心通过事件恢复完整进度，不依赖发起页面的 JavaScript 定时器是否仍存在。

## 5. 状态机与流水线

### 5.1 阶段

```text
queued
→ planning
→ script_quality_check
→ asset_matching
→ match_quality_check
→ preview_rendering
→ preview_quality_check
→ final_rendering
→ final_quality_check
→ succeeded
```

任何运行阶段都可以转入：

- `needs_review`：需要用户只处理问题场景。
- `cancel_requested → canceled`：用户取消。
- `failed`：不可恢复错误。

从 `needs_review` 提交修正后，只从受影响的最近阶段继续，不重复已经通过的脚本生成和 TTS。

### 5.2 幂等与排队

- 同一项目、同一修订、同一生成参数计算固定的 `idempotency_key`。
- 存在 `pending/running/needs_review` 的同键任务时，再次点击直接返回原任务，不创建新任务。
- 一个用户默认最多同时运行一个正式渲染任务；其他项目显示真实队列位置。
- “重新生成”必须创建新修订或明确取消当前任务，不能静默叠加任务。

### 5.3 后台执行器

数据库是队列事实来源。执行器通过租约领取任务并持续写心跳；旧的 `asyncio.create_task()` 不再承担任务可靠性。

- 页面离开不会中断任务。
- 服务重启后，租约到期的任务回到可恢复队列。
- 同时启动 `8080` 和测试端口时，只有持有租约的实例执行任务。
- 执行器每完成一个阶段写入可复用产物和事件。

## 6. AI 对话到视频项目的用户链路

### 6.1 AI 对话

AI 对话的抖音结果卡只保留一个主操作：“生成视频”。点击后：

1. 服务端根据当前对话创建视频项目和首个修订。
2. 返回项目卡和任务 ID。
3. 对话中立即显示阶段、进度、“查看项目”和“取消生成”。
4. 全站任务中心同步出现同一任务。

不再要求用户先手动导入内容编辑器、再进入精准匹配、再写回编辑器。

### 6.2 统一视频项目页

新增 `/video-project.html?id=<project_id>`，作为生成视频的唯一主工作区，包含：

- 顶部：项目状态、总进度、取消/继续/重新生成。
- 脚本区：标题、总口播、事实来源、音色。
- 分镜时间线：每个场景的口播、字幕、目标时长、已选镜头和质量状态。
- 问题面板：只列出阻塞正式成片的场景及原因。
- 预览区：低清预览和最终 MP4。
- 高级编辑入口：修改脚本、替换候选镜头、锁定镜头。

现有内容编辑器继续服务多平台文案；现有精准匹配页继续作为高级镜头选择器，但两者通过项目 API 读写同一修订，不再通过 `localStorage` 传递。

### 6.3 全站任务中心

所有登录页面显示固定任务入口，展示：

- 当前阶段和百分比。
- 队列位置或预计后续阶段，不伪造完成时间。
- “查看项目”。
- “取消生成”。
- 失败后的“从失败阶段重试”。

刷新页面后通过 `GET /api/video-generation/jobs/active` 恢复任务。没有任务时不显示浮层。

## 7. 质量门禁

### 7.1 脚本门禁

硬性检查：

- 4–6 个分镜。
- 每个分镜包含非空口播、画面意图和字幕。
- 总目标时长在 24–40 秒范围。
- 未经来源支持不得包含价格、时效、比例和实时事件结论。
- 口播按选定音色估算后不能明显超过场景可用时长。

失败时自动修复一次；仍失败则进入 `needs_review`，显示具体字段而不是返回空编辑器。

### 7.2 素材匹配门禁

每个场景必须满足：

- 素材处于启用状态且版权状态允许使用。
- 镜头开始和结束时间有效。
- 具有与主体、动作或场景至少一项直接相关的证据。
- 同一镜头不能连续重复；全片重复必须有明确理由。
- 横屏素材用于竖屏时必须标记为“可安全裁剪”或要求人工确认。

综合匹配分达到 85 可自动采用；70–84 生成预览并标记复核；低于 70 自动重新匹配一次，仍不足则进入 `needs_review`。分数只用于路由，不对用户伪装成客观概率。

上述阈值使用经过测试集校准的新质量分，不直接复用当前页面中以关键词重合计算的原始分数（例如现有的 45.28）。在校准完成前，缺少人工确认或直接内容证据的镜头一律不能自动通过。

### 7.3 预览门禁

先生成 540×960 的低清预览，检查：

- 画面不黑屏、不冻结、不严重拉伸。
- 主体未被竖屏裁剪切除。
- 严格执行镜头 `start_ms` 和 `end_ms`。
- 旁白不截断，字幕与旁白时间对齐。
- 字幕不超出安全区，最多两行。
- 无连续重复镜头，转场点与口播停顿基本一致。
- 原声与旁白不存在明显削波或旁白被淹没。

预览不通过时只重做失败场景，最多自动修复两轮；超过两轮进入人工复核，防止无限消耗资源。

### 7.4 正式成片门禁

正式渲染输出 1080×1920、H.264/AAC MP4。必须通过：

- 视频和音频流存在。
- 分辨率、编码和可播放性正确。
- 输出时长与各场景实际时长之和误差不超过 0.35 秒。
- 字幕提示数与有口播场景一致。
- 无丢失场景。
- 使用的素材、授权、镜头时间范围和修订可追溯。

不通过则不标记为 `succeeded`，不允许进入发布队列。

## 8. 取消、恢复与清理

### 8.1 取消行为

- `pending`：立即转为 `canceled`，不进入执行器。
- `running`：转为 `cancel_requested`；执行器在阶段边界检查，并向当前 TTS HTTP 请求或 FFmpeg 进程组发送终止信号。
- FFmpeg 先发送正常终止，短等待后仍未退出再强制终止。
- 未完成的输出文件删除；已完成的脚本、匹配和 TTS 缓存保留，以便后续从对应阶段继续。
- `succeeded/failed/canceled` 再次取消返回当前状态，保证接口幂等。

### 8.2 页面离开与刷新

页面生命周期不控制任务生命周期。重新进入任一页面时，任务中心通过服务端状态恢复进度；项目页通过项目 ID恢复脚本、分镜、预览和质量报告。

### 8.3 服务异常

- 执行器定期更新心跳。
- 服务退出后租约自然过期。
- 下次启动重新领取任务，并从最后一个已完成阶段恢复。
- 不再永久保留历史 `running` 状态。

## 9. API 边界

核心接口：

- `POST /api/video-projects`：从对话或编辑器快照创建项目。
- `GET /api/video-projects/{id}`：读取项目、当前修订和质量状态。
- `PUT /api/video-projects/{id}/revision`：保存脚本、音色或镜头修改并产生新修订。
- `POST /api/video-projects/{id}/generate`：幂等启动或返回已有生成任务。
- `GET /api/video-generation/jobs/{id}`：读取完整任务状态。
- `GET /api/video-generation/jobs/active`：恢复当前用户活动任务。
- `POST /api/video-generation/jobs/{id}/cancel`：请求取消。
- `POST /api/video-generation/jobs/{id}/resume`：复核后从可恢复阶段继续。
- `POST /api/video-generation/jobs/{id}/retry`：从失败阶段创建受控重试。

旧 `/api/douyin/render` 在迁移期转换为创建视频项目和生成任务，避免已有页面立即失效；前端完成迁移后再移除旧路径。

## 10. 对抗式审查

| 攻击场景 | 现设计的防御 |
| --- | --- |
| 用户连续点击三次生成 | `idempotency_key` 返回同一任务 |
| 用户生成中跳到其他页面 | 数据库任务继续，全站任务中心恢复 |
| 用户刷新或关闭浏览器 | 项目和任务均服务端持久化 |
| 用户点击取消后 FFmpeg 仍占资源 | 进程组终止、状态检查和临时文件清理 |
| 同时运行 8080 和测试端口 | 数据库租约确保单任务单执行器 |
| 服务在场景 3 崩溃 | 心跳租约到期后从最后完成阶段恢复 |
| 素材全部横屏但目标是竖屏 | 先做安全裁剪判定；不安全则局部复核 |
| 所有海外仓镜头得分相同 | 缺少直接动作证据时禁止自动通过质量门禁 |
| 模型编造实时事实 | 脚本事实门禁阻止正式生成 |
| TTS 比分镜时间长 | 预估和实测双重检查，调整场景或进入复核 |
| 镜头结束时间被忽略 | 渲染输入严格限制 `start_ms/end_ms` |
| 低清预览通过但高清失败 | 正式渲染后再次执行技术质量门禁 |
| 用户取消后立刻重新生成 | 原任务完成取消确认后，新修订才可入队 |
| 没有足够合格素材 | 明确显示缺少的场景类型，不使用无关素材兜底 |

## 11. 测试与验收

### 11.1 后端状态机

- 相同幂等键只创建一个任务。
- 每个合法和非法状态转换都有测试。
- pending、running、重复取消均得到确定结果。
- 租约到期任务可恢复；有效租约不能被第二执行器领取。
- 失败、取消和恢复不会丢失已完成产物。

### 11.2 渲染器

- FFmpeg 命令同时使用镜头开始和结束时间。
- 取消能终止真实子进程并删除部分输出。
- 旁白较长、视频较短、图片素材、无原声音轨均有覆盖。
- 预览和正式成片质量报告可复现。

### 11.3 前端

- AI 对话一键创建项目并显示任务卡。
- 跨页面和刷新后仍能恢复同一任务。
- 连续点击不会生成多条任务。
- 取消按钮在 pending/running 状态可用，终态不可误操作。
- `needs_review` 只展示问题场景，确认后从正确阶段继续。
- 成功后在 AI 对话和项目页均可播放、下载并进入发布队列。

### 11.4 真实验收脚本

使用“南非海外仓如何完成货物入库和包裹检查”生成 5 个场景。验收要求：

- AI 对话一次点击后无需在三个页面之间手动搬运。
- 切换到内容资产页再返回，任务仍显示真实进度。
- 连续点击生成三次，数据库只有一个活动任务。
- 生成中取消后，任务进入 canceled，系统不存在继续运行的 FFmpeg 子进程。
- 素材证据不足的场景停在局部复核，不自动使用无关镜头。
- 通过门禁后生成可播放的竖屏 MP4，旁白完整、字幕同步、镜头范围正确。

## 12. 迁移和范围

第一阶段交付完整项目状态机、幂等队列、取消/恢复、全站任务中心、统一项目页、现有匹配器接入和技术质量门禁。素材语义证据不足时严格进入复核，不承诺虚假的全自动通过率。

第二阶段在不改变项目 API 的前提下增强镜头理解、智能竖屏重构、转场和声音设计。第一阶段的边界保证这些增强可以替换内部实现，而不再重做 AI 对话到视频项目的联动链路。

## 13. 非目标

- 不在本次重构中自动发布到外部平台。
- 不绕过素材授权确认。
- 不以增加付费模型作为联动链路可靠性的前提。
- 不删除内容编辑器和精准匹配页；它们降级为同一项目的高级编辑视图。
- 不承诺素材不足时仍能无人工介入地产出高质量成片。
