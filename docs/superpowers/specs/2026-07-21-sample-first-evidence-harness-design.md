# 南非热点样本优先证据 Harness 设计

## 1. 决策

本轮采用“方案 B：样本优先的证据 Harness”。目标不是在周五前建设完整 Agent 平台，而是在不编造事实、不滥用网络素材的前提下，用同一套可复用底座产出三份可向领导展示的样本：一条短视频、一组图文和一篇公众号软文。

系统继续坚持真实素材拼接，不把 AIGC 视频作为主要画面来源。模型只负责理解、规划、描述、排序和审查；事实来自可信来源，品牌承接来自 Buffalo 已确认资料，画面来自自有或许可明确的素材。

## 2. 成功标准

### 周五样本

1. 视频：30–45 秒竖屏，包含真实热点钩子、履约问题、Buffalo 解决路径和行动承接。
2. 图文：5–7 页，信息密度适中，事实与视觉来源可追溯。
3. 公众号软文：800–1200 字，包含事实背景、业务解释、风险边界和 Buffalo 承接。
4. 三份样本都能显示事实来源、素材来源和人工确认状态。
5. 没有证据支持的 Buffalo 时效、比例、案例和能力数据不得自动生成。

### 系统底座

1. 管理员可配置南非可信 RSS 来源，系统最多同时启用 5 个；首批预置并逐个验证 5 个互补来源。
2. 同一热点形成一份可复用的事实证据包。
3. 文本、视觉分析、审查和 TTS 可分别选择模型配置。
4. 素材分析结果按文件哈希、模型和提示词版本缓存。
5. 每次内容任务有调用次数、Token 和成本上限；超限停止并提示人工处理。
6. 质量不足时允许生成带明显标记的内部测试预览，但发布级成片继续受质量门禁保护。

## 3. 非目标

- 本轮不建设自治多 Agent 群。
- 本轮不引入独立向量数据库。
- 本轮不自动下载版权不明的新闻、YouTube 或 TikTok 视频。
- 本轮不根据播放量自动训练或调整模型。
- 本轮不实现所有行业和所有南非网站的全网抓取。
- 本轮不承诺无人审核的一键发布。

## 4. 当前事实基线

本地数据库当前有 28 个素材、30 个镜头，其中人工确认标签为 0，ASR 文本为 0；17 个镜头既无 ASR 也无 OCR。可信热点源、热点记录、灵感链接和企业知识文档均为 0。现有内容模型固定为 MiMo v2.5，素材处理没有调用视觉模型，所谓语义匹配主要依赖结构化词表、FTS 和字符重合。

因此第一优先级不是升级大模型，而是建立事实证据、品牌证据和镜头证据。

## 5. 最小架构

```text
可信热点源
  → 事实证据包
  → 内容角度与商业链路
  → 镜头检索与缺口清单
  → 视频/图文/公众号适配
  → 事实、画面、品牌、版权、重复度审查
  → 内部预览或发布级输出
```

### 5.1 可信热点源

第一批最多同时启用 5 个来源，按信息职责互补，而不是把多个相似新闻站重复堆入系统：

| 来源 | RSS | 主要用途 |
|---|---|---|
| SAnews（南非政府新闻机构） | `https://www.sanews.gov.za/south-africa-news-stories.xml` | 综合政务、社会事件、交通与公共服务热点 |
| SARS（南非税务局） | `https://www.sars.gov.za/feed/?post_type=latest_news` | 海关、边境、税务与跨境履约风险 |
| Department of Transport | `https://www.transport.gov.za/?feed=rss2` | 道路、港口、货运与交通运行信息 |
| South African Government | `https://www.gov.za/news-feed` | 政府声明、部门公告和政策信息 |
| South African Reserve Bank | `https://www.resbank.co.za/bin/sarb/solr/publications/rss` | 汇率、利率、支付与宏观金融背景 |

“5 个”是同时启用的硬上限，不是必须凑满的数量。管理员启用第 6 个来源时，系统必须拒绝并提示先停用现有来源；单个来源抓取失败不得阻塞其余来源。来源入选必须满足：HTTPS、可验证发布机构、稳定时间字段、正文可回溯、允许域名明确。RSS 文章默认只作为事实来源；媒体是否可以进入素材库需要单独记录许可。SAnews 明确允许媒体免费使用其站内故事、图片及其他材料，但系统仍需保存来源并由人工确认具体素材的使用边界；其余来源不因“官方”身份自动获得媒体复用许可。

实现验证时，Statistics South Africa 的公开地址向本地抓取器返回 Incapsula HTML 而非 RSS，无法稳定解析，因此不再作为默认启用源；替换为可实际读取的南非交通部 RSS。抓取器同时兼容 XML 声明前的空白字符。

#### 二级热点发现源

IOL South Africa News（`https://iol.co.za/news/south-africa/`，RSS：`https://www.iol.co.za/rss`）作为 `secondary_discovery` 保存，只承担本地热点发现，不占用 5 个官方证据源名额。IOL 内容来自自有采编及多家通讯社聚合，且其条款要求商业使用内容或 RSS 取得许可，因此系统只保存标题、原文 URL、发布者和时间；不得自动抓取全文、不得下载图片或视频、不得作为具体事实的唯一证据。进入内容证据包前，关键事实必须回查对应官方机构或第二个独立来源。

### 5.2 事实证据包

每个热点保存：

- 标题、摘要、发布机构、原文 URL；
- 发布时间、采集时间、事件时间；
- 关键事实列表，每条事实绑定来源 URL；
- 可用视觉链接及其版权状态；
- 适用内容角度和有效期；
- 人工确认状态。

模型只能基于证据包生成事实性陈述。没有来源的具体数字、时效和因果关系必须删除或改为条件式表达。

### 5.3 Buffalo 品牌证据

建立最小内部证据包，至少包含：

- 已确认的服务范围；
- 可公开的仓库、清关、配送流程；
- 可公开的客户案例或订单证明；
- 能否使用的具体时效、线路、覆盖区域和数据；
- 禁止公开的承诺与敏感信息。

热点事实与 Buffalo 能力必须分开检索和引用，避免把外部事件推导成未经证明的品牌成绩。

### 5.4 素材证据

继续使用本地 FFmpeg 切片、OCR 和 ASR。视觉模型只分析代表性关键帧，不逐帧调用。每个镜头至少产生：客观画面描述、地域、场景、主体、动作、情绪、画幅、质量、来源、版权和人工确认状态。

检索顺序：硬条件过滤 → FTS/标签召回 → 可选语义召回 → 业务规则重排。当前素材规模先不引入外部向量数据库；当有效镜头超过 500–1000 个且 FTS Top-3 基线不足时，再增加嵌入检索。

### 5.5 模型路由

模型不按品牌绑定，而按任务角色配置：

| 角色 | 任务 | 默认成本策略 |
|---|---|---|
| `planner_text` | 角度、结构、平台初稿 | 便宜文本模型 |
| `vision_tagger` | 关键帧客观描述和标签 | 多模态模型，按需调用 |
| `critic` | 最终事实、品牌和画面审查 | 较强模型，仅审最终候选 |
| `tts` | 中文旁白 | 独立语音模型 |
| `local` | 切片、OCR、ASR、去重、规则校验 | 本地免费工具 |

每个远程模型配置包含：`provider`、`base_url`、`api_key_env`、`model`、`capabilities`、`timeout`、`max_tokens`、`cost_profile` 和 `enabled`。密钥只读取环境变量，不写数据库、不返回前端。

## 6. 成本控制

1. 本地优先：切片、OCR、ASR、去重和技术质检不调用付费模型。
2. 分层调用：普通规划使用便宜模型，强模型只审最终版本。
3. 内容复用：一个热点只生成一次事实证据包，三种内容共同使用。
4. 结果缓存：缓存键为 `输入哈希 + 模型配置 ID + 提示词版本`。
5. 有界重试：网络错误最多重试一次；质量不合格不无限调用模型修复。
6. 预算熔断：按任务限制调用次数、输入输出 Token 和估算成本。
7. 缺口优先：没有合适画面时输出“缺少什么素材”，不让模型用弱相关镜头掩盖问题。

## 7. 质量 Harness

最终输出必须通过五项检查：

1. 事实：热点陈述能映射到来源，时间和地点没有错位。
2. 品牌：Buffalo 能力和结果有内部依据，不编造时效或案例。
3. 画面：每句核心口播至少有一个可解释候选；低分镜头明确标记。
4. 版权：事实来源与可用媒体分开；版权不明的链接不可进入成片。
5. 差异化：限制同镜头、同来源、同角度在近期任务中的重复使用。

输出分两级：

- 内部测试预览：可以包含低置信度镜头，但必须显示水印和问题清单，不可进入发布队列。
- 发布级输出：所有硬性事实、品牌、版权和技术检查必须通过。

## 8. 首批三个样本

### 8.1 视频

主题：SARS 工业行动期间的边境连续性保障。内容结构为“外部扰动 → 官方保障措施 → 跨境卖家应关注的节点 → Buffalo 可验证的履约准备 → 行动承接”。画面优先使用 Buffalo 自有仓库、扫描、分拣、装车和系统操作素材；热点新闻只负责事实钩子。

### 8.2 图文

主题：南非—纳米比亚贸易合作与区域物流机会。用官方事实说明机会，用地图、贸易、仓库和跨境运输素材解释企业进入区域市场时需要的履约底座。

### 8.3 公众号软文

主题：结合 Stats SA 零售数据，解释“市场需求不等于履约能力”。文章不得在数据正式发布前预写具体结果；数据发布后再形成事实段落和 Buffalo 业务承接。

## 9. 失败处理

- 热点源不可用：按来源隔离失败，保留该来源上次成功快照并标记过期；其他来源继续抓取，不用旧内容冒充今日热点。
- 模型不可用：允许人工填写证据包和内容角度，不用通用模板冒充 AI 成果。
- 素材不足：生成缺口清单，支持人工补充、授权素材化或修改脚本。
- 品牌证据不足：删除具体承诺，改为流程说明或等待内部资料。
- 预算超限：停止远程调用，保留已有中间结果供人工继续。

## 10. 验收

1. 系统预置 5 个官方 RSS，均可独立抓取、去重并保存来源快照；单源失败不影响其余来源。
2. 同时启用数量达到 5 个后，系统拒绝启用第 6 个并给出明确提示。
3. 热点详情能显示事实、来源、时效和视觉版权状态。
4. 管理员能配置四类模型角色，切换模型无需修改业务代码。
5. 同一素材重复分析时命中缓存，不再次调用视觉模型。
6. 三种内容从同一证据包生成时事实保持一致，但结构和画面不完全重复。
7. 无内部证据时，系统会阻止具体 Buffalo 时效和业绩承诺。
8. 低质量任务可以输出带标记的内部预览，但不能误入发布队列。
9. 每个样本任务能查看模型调用次数、估算 Token、估算成本和缓存命中情况。

## 11. 实施顺序

1. 预置并逐个验证 5 个官方热点源，同时实现“最多启用 5 个”和单源失败隔离。
2. 建立事实证据包与 Buffalo 最小内部证据包。
3. 增加模型角色配置、统一调用接口、缓存和预算熔断。
4. 给代表性关键帧补视觉描述并增加人工确认入口。
5. 增加内部测试预览与发布级质量分层。
6. 按三个样本主题完成素材缺口清单和最终样本。

这个顺序优先解决周五输出，不先做与样本无关的复杂 Agent、向量数据库和自动学习系统。
