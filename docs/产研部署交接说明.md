# SA-LogiFlow 产研部署交接说明

> 交付对象：产研、运维同事  
> 部署目标：先部署可用的内部测试/生产单机版本  
> 重要说明：本次部署**不依赖 Huimei CLI**。没有平台官方 API 或现成发布通道的平台，先保留内容生成、审核、排期和人工发布能力，不承诺自动发布。

## 1. 项目简介

SA-LogiFlow 是一个面向南非物流业务的内容运营系统，当前包含：

- 用户注册、登录及个人数据隔离
- 每个人独立维护多平台账号矩阵
- AI 多平台内容生成
- 内容真实性证据与发布门禁
- 南非热点抓取及素材库
- Buffalo 品牌观点内容生成
- 小红书图片卡片生成
- 抖音竖屏视频、逐句字幕、质量检查及可选切片
- 内容审核、发布队列和定时任务
- 多微信公众号账号选择及任务拆分
- 按人员统计的经营驾驶舱和痛点指标
- 热点素材与成片的低磁盘生命周期管理

### 素材保留策略

- Buffalo 原始素材永久保留，不参与自动清理。
- 已下载的热点图片/视频默认保留 7 天；正在生成任务中使用、已置顶或仍有活动引用时跳过。
- 生成完成的视频默认保留 30 天；置顶成片不清理。
- 清理只移除本地媒体文件，来源、发布时间、抓取时间、使用记录和审计记录仍保留。
- 默认 `MEDIA_CLEANUP_DRY_RUN=1`，每天 03:30 只生成清理预览。管理员确认候选无误后，才可改为 `0` 执行删除。
- 磁盘剩余空间低于 15% 时告警，低于 5% 时应停止新素材下载和视频生成。

### 热点视频事件片段

- 热点页的主对象为“热点专题包”，不是单条新闻。专题包保存热度、事件类型、地点、实体、来源信号、媒体计数和确认状态；外部媒体默认只保存链接或内部预览元数据。
- `GET /api/hotspot-packages` 提供专题包列表，`GET /api/hotspot-packages/{id}` 提供信号、媒体和事件片段；确认专题包不下载媒体，`POST /api/hotspot-media/{id}/prepare` 才会启动单个授权媒体的分析。

- 热点下载视频的来源层固定显示为“热点素材”，不会再被资产级分类器归为“配送”或“仓库”。
- 视频分析后按字幕、OCR、地点/机构和镜头边界生成事件片段；事件目标 12～25 秒，内部镜头 3～8 秒。
- 每个事件保存中文标题、英文标题、日期、地点、来源、时间范围和置信度；低置信度事件显示“待确认”，不得自动进入成片。
- 事件预览引用原视频起止时间，不复制新视频文件。
- 成片匹配只能引用“热点事件片段”，不能直接引用热点母片；渲染时使用母片路径加 `start_ms/end_ms`，因此不会为每个事件复制完整视频。
- 平台预算默认：抖音 30 秒、小红书 45 秒、YouTube 60 秒、微信公众号 90 秒；项目也支持 15～180 秒的自定义预算。热点片段和 Buffalo 原有素材共享同一预算，分镜按顺序累计，最后一个跨预算分镜会被裁到剩余时长。
- 视频项目页会展示目标预算、已使用时长和剩余时长；渲染报告保存每个实际使用的 `clip_ref`，便于复核来源和时间范围。
- 运营默认从热点事件卡进入“视频跟进”：先预览事件片段，再自动创建视频项目草稿；“视频精确调整”只作为需要商务/运营人员手动改镜头时的二级入口，不再作为热点素材的默认跳转页。
- 事件预览优先使用母片视频的 `start_ms/end_ms` 时间范围，并以事件缩略图或母片缩略图作为 poster；没有可用本地母片时明确显示预览不可用，不伪造空白视频。
- 事件入库后会生成低清、独立的 `assets/hotspot-events/<asset_id>/event-<id>.mp4` 预览代理文件；素材库播放的是这条短片，不是母片。最终成片仍按母片时间范围渲染，避免把每个代理片当作新的原始资产重复管理。
- 事件代理片单条上限 25 秒；超过上限的连续事件会继续拆成多个带序号的事件片段。已有 SA Today 母片已补生成 10 条事件代理片，最长 25 秒。
- 每个事件分别展示热点镜头 Top 3 与 Buffalo 原有素材 Top 3；无可靠品牌关联时不强行匹配。
- 重建既有热点资产时运行：

```bash
python3 scripts/run_hotspot_event_rebuild.py --asset-id <热点资产ID>
```

- 该命令只重建本地事件和名称，不下载视频、不调用 MiMo。

## 2. 本次交付范围

### 可以直接部署使用

- 注册、登录和权限管理
- 多用户数据隔离
- 内容生成、编辑、保存和审核
- 真实性证据录入与门禁
- 素材上传、素材库管理
- 南非热点 Feed 抓取
- 热点视频事件片段拆分、双语命名与双素材库匹配
- 图片卡片生成
- MiMo TTS 视频生成、字幕对齐、质量检查和切片
- 发布队列与排期
- 多公众号账号矩阵和目标账号任务拆分
- 经营驾驶舱

### 暂不承诺自动发布

由于服务器没有 Huimei CLI，以下能力默认按“生成内容后人工发布”处理：

- 微信公众号自动发布
- 微信视频号自动发布
- 其他原本依赖 Huimei 的国内平台自动发布

注意：系统仍可绑定多个微信公众号、选择目标公众号并分别建立任务，但最后一步需要运营人员复制内容或下载素材后，在公众号后台人工发布。不要因为页面显示了账号和队列，就误认为服务器已经具备公众号官方发布权限。

Facebook、Twitter、Reddit 等平台只有在提供有效官方 API 凭据且适配器验证通过后，才可启用自动发布。

## 4. 推荐服务器环境

- Ubuntu 22.04 或 24.04
- Python 3.11 或 3.12
- 最低 4 核 CPU、8 GB 内存
- 建议预留 50 GB 以上磁盘；视频素材较多时建议 100 GB 以上
- 必须安装 FFmpeg 和 ffprobe
- 如需小红书/抖音浏览器自动化，需安装 Playwright Chromium

## 5. 最简部署步骤

### 5.1 安装系统依赖

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip ffmpeg
```

检查视频依赖：

```bash
ffmpeg -version
ffprobe -version
```

### 5.2 安装 Python 依赖

假设项目放在 `/opt/distribution-manager`：

```bash
cd /opt/distribution-manager
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

如需浏览器扫码或 RPA：

```bash
.venv/bin/playwright install --with-deps chromium
```

### 5.3 创建环境变量

在项目根目录新建 `.env`：

```dotenv
MIMO_API_KEY=填写真实的MiMo密钥
JWT_SECRET=填写至少64位随机字符串
CORS_ORIGINS=https://正式访问域名

PUBLISH_DAILY_LIMIT=10
PUBLISH_MIN_INTERVAL_MIN=30
PUBLISH_JITTER_MIN=5

SA_HOTSPOT_FEEDS_JSON=[]
```

生成 JWT 密钥：

```bash
openssl rand -hex 64
```

测试环境没有域名时，`CORS_ORIGINS` 可暂时填写测试地址，例如：

```dotenv
CORS_ORIGINS=http://10.0.0.20:8080
```

### 5.4 启动

测试启动：

```bash
cd /opt/distribution-manager
source .venv/bin/activate
python3 app.py
```

默认监听：

```text
http://服务器IP:8080
```

正式运行可交给 systemd，但必须保持单进程：

```bash
.venv/bin/uvicorn app:app --host 0.0.0.0 --port 8080 --workers 1
```

不得擅自把 `--workers` 改成 2 或更高。

## 6. 为什么必须单进程

当前版本包含 SQLite、内存扫码会话、内存渲染信号量和应用内定时调度器。多进程会造成：

- 同一个定时任务重复执行
- 扫码状态在不同进程之间丢失
- 同一个视频被并行重复渲染
- SQLite 并发写入压力增大

如果将来需要多实例或容器集群，需要先把数据库迁移到 PostgreSQL，并把调度、视频渲染和浏览器任务拆成独立 Worker。

## 7. 数据和文件持久化

必须持久化以下目录：

```text
data/
static/uploads/
static/assets/library/
static/assets/thumbnails/
logs/
```

如果使用 Docker，这些目录必须挂载到宿主机卷，不能只存在容器内部，否则重新创建容器后用户、内容和素材会丢失。

最低备份要求：

- 每天备份 `data/logiflow.db`
- 每天或每周增量备份 `static/uploads/`
- 上线、升级前分别备份数据库和素材目录
- 至少保留 7 天备份

备份 SQLite 前建议停止应用，或者使用 SQLite 的 `.backup` 命令。

## 8. 首次启动后的必要操作

系统当前会在数据库为空时创建默认管理员：

```text
用户名：admin
密码：admin123
```

首次启动后必须立即处理：

1. 登录默认管理员。
2. 创建正式管理员账号。
3. 修改或禁用默认管理员。
4. 不允许长期保留 `admin123`。

如果系统对公网开放，建议产研在上线前进一步修改代码：生产环境不再自动生成固定密码，而是通过环境变量或初始化命令创建管理员。

## 9. 公开注册注意事项

当前注册页允许用户自行注册，公开注册用户固定为编辑角色，不能自行注册成管理员。

如果这是公司内部系统，建议：

- 只允许公司内网或 VPN 访问；或者
- 在网关增加统一登录；或者
- 关闭公开注册，只允许管理员创建用户。

不要只依靠“别人不知道网址”作为安全措施。

## 10. 素材和视频注意事项

- 视频生成依赖 `MIMO_API_KEY`、FFmpeg 和 ffprobe。
- 素材和生成视频会持续占用磁盘，需要配置磁盘监控。
- 上传目录不可设置成临时目录。
- 生成视频必须通过质量门禁后才能作为合格成片使用。
- 真实 MiMo 视频生成会产生 API 调用费用。
- 首次部署必须生成一条真实样片，人工核对声音、字幕和切片。

## 11. 南非热点抓取注意事项

- 热点抓取器不会凭空搜索整个互联网，只读取管理员配置的可信 RSS/Atom Feed。
- `SA_HOTSPOT_FEEDS_JSON=[]` 表示当前没有通过环境变量配置 Feed。
- 也可以由管理员在素材库页面添加可信来源。
- 来源必须使用 HTTPS，并配置允许域名。
- 热点图片只有在版权许可明确时才允许进入素材库。
- 新闻网页的普通配图只作为候选，不应自动当作可商用素材。
- Buffalo 观点必须和事实速览分开，不能将宣传内容写成新闻事实。

## 12. 微信公众号交付说明

没有 Huimei CLI 时，本项目对微信公众号提供的是：

- 绑定多个公众号账号记录
- 在编辑器选择一个或多个目标公众号
- 同一篇文章按公众号拆成独立任务
- 独立审核、排期和状态跟踪
- 人工复制正文、下载图片或视频后发布

当前不提供：

- 无凭据直接登录公众号后台
- 绕过公众号官方权限自动发布
- 保证所有公众号都能使用官方发布 API

如果后续要实现真正的自动发布，产研需要单独评估微信公众号官方接口、服务号/订阅号权限、草稿箱接口、发布接口和素材上传接口，不应在本次部署中临时模拟“自动发布成功”。

## 13. 浏览器扫码和人工发布限制

小红书、抖音扫码登录和手动发布会使用 Chromium。纯命令行服务器没有桌面时，浏览器窗口无法直接展示给运营人员。

因此测试环境可以先不验收有头浏览器人工发布。若确实需要，应由产研增加以下一种方案：

- Xvfb + noVNC 远程桌面
- 将扫码二维码和状态回传到系统前端
- 独立部署浏览器 Worker

不要把服务器 SSH 窗口当作可操作的扫码界面。

## 14. 上线安全要求

- 必须设置新的 `JWT_SECRET`
- 必须处理默认管理员密码
- `.env` 权限设置为仅应用用户可读
- 不能把 API Key、Cookie、Token 写进 Git、日志或交接文档
- 正式环境建议由 Nginx 或公司网关提供 HTTPS
- 只开放必要端口
- 定期更新系统、Python 依赖和 Chromium
- 对数据库和素材目录设置访问权限
- 正式域名下不要使用 `CORS_ORIGINS=*`

## 16. 当前已知事项

- 当前适合单机、单进程部署，不适合直接做多实例集群。
- 无 Huimei CLI 时，国内平台自动发布不在本次交付范围。
- 服务器上的有头浏览器扫码需要额外远程桌面或二维码回传方案。
- 当前完整测试集存在一处 Twitter 适配器与测试契约冲突；除该测试外，最近一次回归为 91 项通过。产研若要启用 Twitter，需先单独修复并重新完成全量测试。
