# 批22｜Buffalo 品牌结束语语料库与场景匹配执行文档

## 目标

解决所有视频片尾固定为「南非发货，先理清订单信息」的问题。片尾仍保持一张 Buffalo 品牌尾卡、约 3 秒、自动合成 TTS 和字幕，但旁白与字幕必须根据结构化物流场景选择，突出 Buffalo 的可见优势：节点清晰、动作可核对、异常可留痕、交接更稳。

用户示例“南非发货，选择 Buffalo 物流，您在南非最好的物流拍档”作为方向参考；系统语料采用“值得信赖/更清晰/更稳妥”等可复用表述，避免未经证明的绝对化比较承诺。

## 十条语料

| ID | 场景 | 结束语 |
|---|---|---|
| general_partner | 通用 | 南非发货，选择 Buffalo 物流，做您在南非值得信赖的物流拍档。 |
| port_rail_container | 港口/铁路/集装箱 | 港口和干线变化要提前看，选择 Buffalo，让节点衔接更有准备。 |
| customs_clearance | 清关/海关/口岸 | 清关资料先核对、节点再安排，选择 Buffalo，让跨境发货少一点盲区。 |
| road_transport | 道路/运输/路线 | 路况会变，计划不能靠猜；选择 Buffalo，把运输节点和后续安排说清楚。 |
| warehouse_storage | 仓储/入库/库存 | 货到仓后，存放、分拣、出库都要有章法；Buffalo，让仓配每一步更清楚。 |
| sorting_handoff | 分拣/打包/订单交接 | 订单多的时候，分拣和交接更要可核对；选择 Buffalo，让仓内动作接得更稳。 |
| last_mile_delivery | 末端/配送/交付 | 从仓库到客户手里，最后一公里同样重要；选择 Buffalo，让交付安排更清晰。 |
| safety_exception | 安全/风险/异常 | 遇到异常先把风险说清，再安排下一步；Buffalo，让物流动作更可核对、更稳妥。 |
| cost_efficiency | 成本/降本/效率 | 降本不是少做一步，而是把每个物流节点安排好；选择 Buffalo，让成本和交付更有依据。 |
| peak_season_scale | 旺季/增长/电商订单 | 旺季订单来了，仓配和配送要提前协同；选择 Buffalo，让南非发货更从容。 |

## 匹配规则

1. 优先读取 `planning_brief.logistics_nodes`，节点命中权重高于普通主题文本。
2. 节点为空时，读取 `logistics_topic`、`angle`、`claim`、热点标题和摘要进行补充匹配。
3. 同一主题只选择一条确定性语料，并把 `outro_id` 写入脚本快照，便于回溯。
4. 无明确场景时使用 `general_partner`，不再回退到旧的“先理清订单信息”。
5. 结束语只表达 Buffalo 的品牌定位与可见动作优势，不把品牌尾卡当成热点事实证据，不承诺绝对时效、安全或覆盖结果。
6. 片尾仍不占用热点/自有视频镜头槽位，也不改变 50–90 秒正式时长门禁。

## 验收

- 语料库正好 10 条，ID 唯一；
- 港口、清关、末端、仓储、安全、旺季等节点各能选到对应结束语；
- 生成脚本最后一镜包含 `outro_id`、品牌尾卡路径、旁白和字幕；
- 旧固定文案不再出现；
- 原有视频渲染、音频、时长和品牌尾卡测试全部保持通过。
