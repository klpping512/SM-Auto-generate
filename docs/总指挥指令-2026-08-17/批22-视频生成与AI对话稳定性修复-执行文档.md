## 2. 已确认的故障事实

### 2.1 视频项目生成失败

项目：`2d5b3b49-82c3-43a8-99b1-92308e5cf8be`

- 两次任务均在 `scripting` 阶段失败，进度 10%。
- 后端错误：`502: 内容规划失败：内容规划模型缺少标题、角度或有效分镜`。
- `planner_text` 当前路由为 MiniMax-M3。
- 首次模型返回了标题、角度、分镜均为空的 JSON；两次修复调用仍返回空字段。
- 第一次无效结果被写入模型缓存；第二次重试全部命中同一批坏缓存，因此重复失败。
- 项目尚未进入素材匹配、预览渲染或最终渲染；页面显示素材 `0/0` 是前置脚本失败的结果，不是素材库被清空。
- 该项目仍是旧的 `hotspot_owned` 链路，锁定 Hook 为事件 `48`，不是最新的 `owned_only` 直出链路。
- 首次修订记录是 `minimax` TTS，后续修订变成 `mimo`，证明 TTS 选择在重试/修订时被默认值覆盖。

### 2.2 AI 对话请求失败（HTTP 500）

云端日志记录了至少两次 `/api/ai/chat` 返回 500，业务异常一致：

```text
PermissionError: [Errno 13] Permission denied:
/opt/distribution-manager/static/uploads/image/xhs-*.png
```

调用链为：

```text
POST /api/ai/chat
→ ai_chat()
→ _render_xhs_carousel()
→ xhs_cards.render_carousel()
→ PIL.Image.save()
→ PermissionError
```

模型请求本身返回 `HTTP 200 OK`。截图中“小红书”平台处于选中状态，所以对话生成完成后进入了小红书轮播图渲染；云端服务用户 `logiflow` 无法写入 `static/uploads/image/`，未捕获异常被 FastAPI 直接转成 500。

这不是模型额度耗尽，也不是网络超时；是云端部署后的文件权限回归。

## 3. 修复目标

修复完成后必须满足：

1. AI 对话选中小红书时，能在云端正常生成图片文件，不再因目录权限返回 500。
2. 任一平台的图片渲染失败不得拖垮整次对话；接口应返回可识别的部分成功/失败信息。
3. 内容规划模型返回空标题、空角度、空分镜时，不得写入模型缓存。
4. 规划修复请求必须绕过同一条无效缓存，重新请求模型；不能重复命中坏结果。
5. 视频项目重试必须保留用户选择的 TTS 提供商和音色。
6. 失败项目显示具体阶段和原因，不能只显示“生成失败”。
7. 不放宽 Hook 真实性、物流场景、视觉审核和文案门禁；本次只修稳定性和错误可观测性。

## 4. 执行顺序

### 阶段 A：云端权限修复与冒烟

在停止/重启服务前先备份服务配置和数据库。只处理目标目录，不递归修改整个项目：

```bash
cd /opt/distribution-manager
install -d -o logiflow -g logiflow -m 775 static/uploads/image
chown -R logiflow:logiflow static/uploads/image
find static/uploads/image -type d -exec chmod 775 {} \;
find static/uploads/image -type f -exec chmod 664 {} \;
```

用服务用户验证实际写入能力：

```bash
runuser -u logiflow -- sh -c \
  'f="/opt/distribution-manager/static/uploads/image/.write-test-$$"; \
   printf test > "$f" && rm -f "$f"'
```

验收：命令退出码为 0；不能只检查 root 能否写入。

### 阶段 B：对话接口隔离平台失败

修改 `app.py` 的 `ai_chat()` 和小红书图片渲染调用：

- 小红书渲染异常时记录平台、异常类型、输出 ID；
- 保留其他平台的正常文本结果；
- 返回结构化 `platform_errors`，前端显示“文案已生成，小红书配图失败，请重试配图”，不显示笼统 500；
- 只有所有平台都失败时才返回明确的 502，并带业务原因；
- 不把异常堆栈、密钥或内部路径直接返回给浏览器。

### 阶段 C：规划模型缓存加固

修改 `model_router.py` 与视频规划调用：

- 将“可见文本非空”与“规划 JSON 有效”分开校验；
- 规划结果必须同时满足：标题非空、角度非空、分镜数量正确、每段旁白和字幕有效；
- 语义校验失败的响应不得进入 `model_call_cache`；
- 修复调用使用新的缓存键或显式 `use_cache=False`，避免复用坏响应；
- 保留有效规划缓存，避免正常请求被全部改成强制绕过缓存；
- 失败日志记录 `role`、`model`、`prompt_version`、校验失败类型和重试次数，不记录密钥与完整敏感提示词。

### 阶段 D：TTS 选择持久化

- 从聊天创建视频项目时，将 `tts_provider` 和 `voice` 写入项目源快照；
- 每次重试/修订从当前项目快照读取，不用全局默认值覆盖；
- 页面展示值、请求值、修订记录值必须一致；
- MiniMax 和 Mimo 缺少对应密钥时，只阻止对应 TTS，不改变用户已经选择的提供商。
