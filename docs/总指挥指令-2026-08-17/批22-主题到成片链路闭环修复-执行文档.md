> 当前状态：未开始修复，批22阶段B（15→50）继续锁定

## 一、事件判定

本次问题按生产链路故障处理，不按“暂时没有合适素材”处理。

用户输入物流主题“Transnet 又有动静！跨境卖家先别慌”后，系统出现以下行为：

1. 文案草稿成功生成；
2. 文案明确包含港口、铁路、集装箱、FBA、海外仓等物流切入；
3. 系统提示“视频素材补采中”“等待热点 Hook”；
4. 页面没有自动完成主题匹配、定向抓取、Hook 确认和成片入口；
5. 页面列出的候选 Hook 与当前 Transnet 主题不完全匹配。

这说明链路在“主题 → 物流候选 → 已确认 Hook → 视频项目”之间断开。后台六小时调度可以作为常规补库，但不能阻塞用户当前已经明确的物流主题。

## 二、修复目标

同一条输入必须闭环到以下三种可解释结果之一：

| 结果 | 前端行为 | 允许情况 |
|---|---|---|
| 已有匹配 Hook | 直接显示“创建 60 秒视频项目” | 现有 Hook 已满足来源、视觉、文本、物流切入门禁 |
| 正在定向采集 | 显示任务 ID、候选数、当前阶段、预计下次动作 | 已创建真实采集任务，不能只显示一句“补采中” |
| 无法成片 | 显示明确失败原因、已检查信源和建议动作 | 采集确实完成且没有任何合格候选 |

禁止出现“文案已生成，但没有任务证据、没有进度、没有成片入口”的悬空状态。

## 三、不可改变的质量原则

本次修复不得通过放宽门禁解决问题：

- 不得把综合新闻、政治、体育、采访或演播室画面冒充物流 Hook；
- 不得把 `hotspot` 标签冒充港口、道路、仓储、边境或配送场景；
- 不得跳过真实来源、授权状态、下载状态、三帧证据、`ffprobe` 和事实核验；
- 不得为了生成视频强行绑定与主题无关的 Hook；
- 不得把“已审计”直接当作“可直接成片”；
- 不得因本次问题顺便开启 15→50 补库；
- 模型切换不属于本问题的修复手段，先保证链路状态和素材闭环。

## 四、目标链路

```text
用户主题
  ↓
主题结构化：主体、事件、地区、物流节点、时间窗口
  ↓
检索现有 ready Hook
  ├─ 有匹配 → 绑定 Hook → 生成物流桥接文案 → 创建视频项目
  └─ 无匹配
       ↓
    创建带 topic_id 的定向采集任务
       ↓
    优先官方物流信源和物流新闻信源
       ↓
    下载 → 分析 → 事实核验 → 物流切入核验 → confirmed Hook
       ↓
    自动回填当前主题 → 开放创建视频项目
```

六小时常规调度只负责持续补库，不能替代用户请求触发的定向采集任务。

## 五、执行阶段

### 阶段 0：建立故障快照

只读执行，不重启、不清理、不改数据库。

```bash
cd /opt/distribution-manager
uname -a
git rev-parse --short HEAD
systemctl status salogiflow --no-pager
journalctl -u salogiflow -n 200 --no-pager
```

记录当前请求对应的：

- 原始主题文本和平台；
- chat 请求时间、请求 ID、会话 ID；
- 文案生成结果；
- 候选 Hook ID、匹配分数、过滤原因；
- 是否创建了定向采集任务；
- 任务状态、`next_run`、候选数量和失败原因；
- 当前 `ready`、`audit_only`、`confirmed`、`logistics_question` 数量；
- 服务提交号、数据库备份路径和当前环境变量摘要。

阶段 0 必须回答：截图里的“已立即复扫”到底对应真实数据库任务，还是只有一段前端文案。没有任务记录时，判定为 P0 状态欺骗性提示缺失。

### 阶段 1：修复主题结构化与匹配

为每个主题生成结构化检索条件，至少包括：

```json
{
  "topic": "Transnet又有动静！跨境卖家先别慌",
  "entities": ["Transnet", "南非"],
  "logistics_nodes": ["港口", "铁路", "集装箱", "跨境运输", "仓储"],
  "scene_terms": ["港口作业", "铁路运输", "堆场", "装卸", "排队", "延误"],
  "time_window_days": 30
}
```

匹配不得只看标题相似度，至少综合：

- 主题实体命中；
- `what_happened` 事实命中；
- `logistics_question` 与物流节点命中；
- 真实物流场景命中；
- 来源类别和时效；
- `ready`、可播放、授权和事实核验状态。

匹配结果必须分成：

- `matched_ready`：可直接成片；
- `matched_audit_only`：相关但不可成片，显示具体缺口；
- `unmatched`：没有相关候选，触发定向采集。

不得把无关 Hook 填充到 `matched_ready`。

### 阶段 2：修复定向采集触发

当 `matched_ready=0` 时，后端必须创建真实任务，任务参数至少包含：

```text
job_type=topic_targeted_hotspot_intake
topic_id 或 chat_request_id
entities
logistics_nodes
source_classes=[official_logistics, logistics_news]
time_window_days
max_candidates
```

执行顺序：

1. 先查当前已授权的 Transnet NPA、SANRAL、海关、边境、港口和铁路信源；
2. 再查明确报道物流、港口、运输、供应链的可信新闻源；
3. 最后才允许使用综合新闻源中的真实物流现场画面；
4. 每个候选必须落入 `topic_id` 对应的任务，不得只写入普通全量队列；
5. 任务完成后自动重新执行主题匹配，不需要用户重新提交主题。

任务状态至少包括：

```text
queued → fetching → downloading → analyzing → reviewing → matched → ready
                                                     └→ no_match / failed
```

前端必须展示真实状态，不得在没有任务 ID 时显示“已立即复扫”。

建议配置项：

```text
TOPIC_HOOK_AUTOFETCH_ENABLED=1
TOPIC_HOOK_AUTOFETCH_TIMEOUT_SECONDS=120
TOPIC_HOOK_AUTOFETCH_MAX_CANDIDATES=20
TOPIC_HOOK_AUTOFETCH_SOURCE_CLASSES=official_logistics,logistics_news,general_news
```

超过交互等待时间时，任务继续后台运行，但前端保留任务 ID、阶段和轮询入口。

### 阶段 3：修复 Hook 到 Buffalo 的桥接

Hook 不是单独成片，必须为每个主题生成“热点事实 → 物流影响 → Buffalo 优势”的文案桥接。

统一结构：

1. 第一镜：准确交代 Hook 发生了什么，不夸大、不误归因；
2. 第二镜：说明该事件对货物、港口、铁路、道路、仓储或配送的具体影响；
3. 第三镜及以后：使用 Buffalo 自有素材展示核对、分拣、仓储、运输或交付动作；
4. 结尾：把可见动作转化为 Buffalo 的安全性、稳定性和可追踪优势。

禁止生成以下空泛承接：

- “异常后，Buffalo 核对仓内分拣”；
- “接下来看看我们的解决方案”；
- “这就是物流安全的重要性”。

每个承接句必须能回答：发生了什么风险、影响哪个物流节点、Buffalo 做了什么、为什么体现品牌优势。

### 阶段 4：修复前端状态和按钮

聊天卡片必须显示：

- 主题匹配状态；
- 已检查的 Hook 数量；
- 匹配候选及过滤原因；
- 定向任务 ID；
- 当前阶段和最近更新时间；
- 失败/等待原因；
- 成功后的 Hook ID 和“创建 60 秒视频项目”按钮。

当存在 `matched_ready` 时，按钮必须打开当前主题绑定的 Hook，不能让用户再次从全库盲选。

当只有 `audit_only` 时，按钮保持关闭，并明确说明缺少什么，不得只写“等待热点 Hook”。

### 阶段 5：测试和抗式审查

至少覆盖以下场景：

| 场景 | 预期 |
|---|---|
| Transnet 主题已有 ready 港口 Hook | 自动绑定并开放成片 |
| Transnet 主题只有 audit Hook | 显示物流切入/播放等具体缺口，不开放成片 |
| Transnet 主题没有候选 | 创建定向采集任务并显示任务 ID |
| 只有道路 Hook、主题是港口铁路 | 不误匹配，继续定向采集 |
| 只有综合新闻 Hook | 不冒充物流 Hook，受新闻比例限制 |
| 定向采集下载失败 | 显示失败原因和 retry_after，不伪报“已补采” |
| 任务完成后刷新页面 | 能恢复任务和候选状态，不要求重发主题 |
| 服务重启 | 不丢失 topic_id、job_id、next_run 和失败状态 |
| 同一主题重复提交 | 幂等，不重复创建无界采集任务 |
| 生成 60 秒视频 | 首镜为选定 Hook，后续物流桥接和 Buffalo 素材连贯 |

必须补充端到端测试证据：

- API 请求/响应；
- 数据库任务记录；
- 关键服务日志；
- Hook 绑定记录；
- 视频项目 ID；
- 成片文件和 `ffprobe`；
- 字幕、画幅、遮罩和镜头顺序检查。
