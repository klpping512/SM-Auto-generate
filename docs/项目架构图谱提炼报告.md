## 2. 项目主干

SA-LogiFlow 是一个 Python/FastAPI + SQLite + 静态 HTML 的社媒内容生产中枢，主入口是 `app.py`，数据访问集中在 `database.py`，前端页面位于 `static/`。

核心业务链路：

```text
热点信源
  → hotspot_fetcher.py
  → hotspots / hotspot_media
  → media_assets.py / asset_processing.py
  → asset_segments + semantic_matching.py
  → hotspot_event_clips.py / hotspot_event_matching.py
  → video_generation.py / video_renderer.py
  → video_quality/
  → 发布适配器 adapters/
```

## 4. 主要社区/子系统

### 热点与素材

- `hotspot_fetcher.py`：可信信源、RSS/网页抓取、热点记录。
- `hotspot_media.py`：图片/视频候选发现、来源页校验、下载和权利状态。
- `hotspot_video_sources.py`：YouTube 等视频来源解析。
- `media_assets.py`、`local_asset_import.py`：素材入库和本地目录导入。
- `media_retention.py`：已使用素材清理、容量控制。

### 事件拆分与匹配

- `asset_processing.py`：转写/OCR/镜头边界/语义片段处理。
- `hotspot_event_clips.py`：根据已有字幕、OCR 和镜头证据生成双语事件时间片段。
- `hotspot_event_matching.py`：热点事件和 Buffalo 原有素材分开排名。
- 当前状态：事件片段已成为独立虚拟素材引用，写入视频时间线；渲染按母片路径和时间范围裁剪，不复制整条母片。

### 视频生成与质检

- `video_generation.py`：阶段化视频生成任务、取消、重试和状态机。
- `video_renderer.py`：字幕、Logo、水印和视频渲染。
- `video_quality/technical_validator.py`：ffprobe/ffmpeg 技术检测。
- `video_quality/frame_extractor.py`：高效/均衡/详细抽帧和重复帧去重。
- `video_quality/transcript_service.py`：字幕优先、Whisper 降级。
- `video_quality/video_evaluator.py`：MiMo 严格 JSON 质检。
- `video_quality/prompt_optimizer.py`：低分报告转下一轮提示词。

### 发布与运营

- `adapters/`：抖音、小红书、Twitter、Facebook、Reddit 等平台适配器。
- `scheduler.py`：定时发布、热点抓取和媒体清理调度。
- `publisher.py`：统一发布编排。

## 5. Graphify 揭示的三条重要结论

1. **当前项目不是单一“AI 生成视频”应用**，而是“热点证据 → 素材预处理 → 事件/镜头匹配 → 视频生成/渲染 → 质检 → 多平台发布”的流水线。
2. **`database.py` 和 `app.py` 是高耦合中心**。增加事件虚拟素材、时长预算或新状态时，应优先定义独立数据契约和服务函数，避免继续把逻辑堆到入口文件。
3. **视频质量模块已经具备成本门控基础**。事件片段时间范围和平台总时长预算现已贯通到规划、匹配和渲染；下一步主要风险是用真实本地视频完成一次端到端人工验收。

## 6. Graphify 的适用边界

适合：

- 离线理解代码、文档和调用关系；
- 影响分析，例如“修改 `render_job()` 会影响哪些测试和发布流程”；
- 交接时快速定位热点、素材、视频生成和质检模块；
- 生成架构图和查询入口。

不适合直接替代：

- `video_quality` 的 ffmpeg/ffprobe 预处理；
- `hotspot_event_clips` 的事件切片逻辑；
- MiMo 调用和视频生成状态机；
- SQLite 运行时业务数据分析。

Graphify 的视频扩展主要是下载/转写，不能替代本项目现有的视频技术检测、关键帧、字幕时间轴和事件切片服务。

## 7. 后续建议

1. 保持 Graphify 为开发期离线工具，不安装进生产依赖。
2. 继续用真实本地视频完成一次端到端验收，重点确认事件时间范围、字幕、音轨和总时长预算。
3. 后续若需要文档/图片/视频语义图谱，优先使用本地 Ollama 或已批准的后端，不把 MiMo Key 或未授权素材交给未知模型服务。
4. 代码变更后可用 `graphify update .` 增量刷新图谱；不需要每次全量重跑。
