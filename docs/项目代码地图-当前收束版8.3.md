# SA-LogiFlow 项目代码地图（当前收束版）

> 更新时间：2026-08-03
> 定位：这不是 Graphify 的自动关系图，而是给后续开发、交接和排障用的人工收束地图。最新离线图谱见 `docs/项目架构图谱提炼报告.md` 和 `docs/graphify-out/GRAPH_REPORT.md`。

## 1. 一句话定位

SA-LogiFlow 现在已经不是单纯的“社媒发布工具”，而是一个面向南非物流内容运营的本地内容中枢：

```text
热点/自定义选题
  -> 事实与品牌证据
  -> 热点素材库 + Buffalo 原有素材库
  -> 语义匹配与双素材锁定
  -> 视频项目/图文/长文生成
  -> 技术与语义质检
  -> 发布队列与平台适配器
```

## 2. 当前主干分层

| 层级 | 主要文件 | 职责 | 当前状态 |
|---|---|---|---|
| Web/API 编排 | `app.py`、`routes/` | FastAPI 启动、路由注册、尚未拆出的热点/聊天 API、后台任务调度入口 | `app.py` 约 4414 行；认证、页面、配置、视频生成路由已拆出，仍需继续薄化 |
| 数据访问 | `database.py`、`repositories/` | SQLite 表结构、迁移、DAO、任务租约、审计日志 | `database.py` 约 4408 行；已建立用户仓储 facade，其余领域仍待拆分 |
| 请求/响应模型 | `models.py` | Pydantic 请求体、平台枚举、视频/选题/素材相关输入契约 | API 边界集中点 |
| 前端壳层 | `static/*.html`、`static/common.js`、`static/design-system.css` | 静态 HTML 单页、公共导航、API 请求、视频任务中心、设计系统 | 无构建步骤，浏览器直连 8080 服务 |
| AI 与模型路由 | `ai_engine.py`、`model_router.py` | 内容生成、多平台文案、模型角色路由、预算/缓存 | 需要持续控制成本和 JSON 失败兜底 |
| 发布 | `publisher.py`、`scheduler.py`、`adapters/` | 发布队列、定时任务、平台适配、账号登录态 | RPA/API 混合，发布前仍依赖队列和审核状态 |

## 3. 业务域地图

### 3.1 认证、账号、队列、审核

- `auth.py`：JWT、密码哈希、当前用户和角色校验。
- `models.py`：`LoginRequest`、`SignupRequest`、`QueueCreateRequest`、`ReviewRequest`、`AccountCreateRequest` 等 API 契约。
- `database.py`：`users`、`accounts`、`queue`、`publish_log`、`audit_logs` 表及相关 DAO。
- `routes/auth_routes.py`：`/api/auth/*`、`/api/users/*`；`app.py` 仍承接 `/api/accounts/*`、`/api/queue/*`、`/api/review/*`、`/api/publish/*`。
- `repositories/users.py`：用户 DAO 的兼容 facade，底层暂时仍调用 `database.py`。
- `static/login.html`、`static/accounts.html`、`static/queue.html`、`static/review.html`、`static/home.html`。

维护要点：权限入口在 `Depends(get_current_user)` 和 `require_role(...)`；所有影响业务状态的动作应写 `add_audit_log()`。

### 3.2 内容生成与编辑

- `ai_engine.py`：普通内容生成、平台文案、对话式内容生成、抖音结构化分镜。
- `topic_library.py`：内置物流选题分类。
- `xhs_cards.py`：小红书 3:4 卡片生成。
- `douyin_copywriting_sop.py`：抖音文案/分镜 SOP。
- `publisher.py`：生成内容入队后的发布编排。
- `static/chat.html`：AI 对话第一入口，含选题、平台、历史对话、双素材视频入口。
- `static/editor.html`、`static/editor-transfer.js`：内容编辑器、分镜编辑、素材关联。

维护要点：生成内容可以进入编辑器或队列；事实类内容不能绕过证据包和发布就绪检查。

### 3.3 热点采集与专题包

- `hotspot_fetcher.py`：热点源抓取、信源归一、抓取运行状态。
- `hotspot_topic_packages.py`：确定性热点信号清洗、聚类、热度评分、物流相关性。
- `hotspot_package_service.py`：专题包列表、详情、确认、信号合并、媒体准备。
- `hotspot_media.py`：原文媒体发现、图片/视频候选、下载和授权状态。
- `hotspot_video_sources.py`：YouTube 等视频链接解析。
- `hotspot_content.py`、`hotspot_preview_narration.py`：热点草稿和预览叙事。
- `database.py`：`hotspots`、`hotspot_signals`、`hotspot_media`、`hotspot_sources`、`hotspot_fetch_runs`。
- `app.py`：`/api/hotspots/*`、`/api/hotspot-packages/*`、`/api/hotspot-media/*`、`/api/hotspot-sources/*`。
- `static/hotspots.html`：热点选题工作台。

维护要点：专题包确认是热点进入内容生产的关键闸口；媒体权利状态要保守，不能默认可发布。

### 3.4 双素材库与素材预处理

- `media_assets.py`：上传/入库、缩略图、文件校验、素材元数据。
- `local_asset_import.py`：本地目录批量接入、去重、任务进度。
- `asset_processing.py`：素材分类、OCR/ASR、镜头边界、语义标签、处理计划。
- `semantic_matching.py`：口播/分镜语义原子与素材片段候选匹配。
- `inspiration_assets.py`：灵感链接入库、授权确认、素材化。
- `media_retention.py`：存储清理、引用保护、保留期策略。
- `database.py`：`assets`、`asset_segments`、`asset_segment_tags`、`asset_processing_jobs`、`local_asset_import_jobs`、`inspiration_items`、语义匹配相关表。
- `static/assets.html`：原有素材库、热点素材库、Hook 素材、灵感池、批量接入和清理预览。

维护要点：当前产品有两套素材来源，Buffalo 原有素材适合长期复用，热点素材有生命周期和权利边界；成片只能引用通过门禁的素材片段。

### 3.5 热点 Hook、事件片段与物流切入

- `hotspot_lexicon.py`：热点/物流匹配词表与双语分词的单一真相源（类别、事件类型、Hook 评分词、feed 过滤、节点扩展、`extract_terms` / `overlap_score`）。
- `hotspot_hook_intake.py`、`hotspot_intake_sop.py`：热点素材入库和可用性判断；检索分词走 lexicon。
- `hotspot_hook_curator.py`、`hotspot_hook_selector.py`、`hotspot_hook_selection_sop.py`：热点 Hook 策展、筛选、质量门禁。
- `hotspot_event_clips.py`：从母片字幕/OCR/镜头证据生成事件级虚拟素材。
- `hotspot_event_matching.py`：热点事件片段与 Buffalo 原有素材分开匹配（含中文 term）。
- `hotspot_event_media.py`：事件媒体状态和素材化辅助。
- `hotspot_logistics_planner.py`：把热点事件转成物流内容角度；`EVENT_TYPES` 与 topic packages 共用 lexicon。
- `video_clip_refs.py`：视频脚本中素材片段引用的校验和归一。
- `database.py`：`hotspot_event_clips`、事件资产引用和清理相关 DAO。

维护要点：母片不是直接素材，真正进入视频时间线的是事件片段引用；这条边界可以防止“整条热点视频乱剪”。新增匹配词必须先进入 `hotspot_lexicon.py`，不要在 app/planner/selector 再散落一份。

### 3.6 选题简报与双素材视频生成

- `app.py` 中 `TopicBrief*` API：自定义主题、证据召回、推荐热点、自动生成视频。
- `truth_guard.py`：事实约束和不可证实表述拦截。
- `evidence_harness.py`、`sample_harness.py`：事实 claim、品牌证据、样本包生成。
- `hotspot_video_planner.py`：热点跟进视频规划。
- `video_duration_budget.py`：平台总时长和分镜时长预算。
- `video_composition_policy.py`：热点/自有/图片素材占比与解释镜头策略。
- `static/video-project.html`、`static/video-followup.html`、`static/video-workbench.html`：视频项目、热点跟进、素材匹配工作台。

维护要点：选题简报是“自由输入”进入严肃生产链路的结构化入口；所有正式视频必须可回溯到热点证据、品牌证据和素材引用。

### 3.7 视频生成、渲染与质量门禁

- `video_generation.py`：持久化视频生成状态机、任务幂等、租约、取消、重试、人工验收。
- `routes/video_generation_routes.py`：视频项目、生成任务、人工验收和视频质检 API。
- `video_renderer.py`：TTS、字幕、Logo、水印、竖屏 MP4 合成。
- `video_quality/`：
  - `schemas.py`：质检输入/输出契约。
  - `technical_validator.py`：ffprobe/ffmpeg 技术检查。
  - `frame_extractor.py`：抽帧与去重。
  - `transcript_service.py`：字幕优先、ASR 降级。
  - `video_evaluator.py`：模型语义质检和严格 JSON 解析。
  - `prompt_optimizer.py`、`regeneration_controller.py`：低分报告转修复建议。
  - `service.py`、`video_preprocessor.py`、`source_resolver.py`：质检编排。
- `database.py`：`video_projects`、`video_project_revisions`、`video_generation_jobs`、`video_generation_events`、`video_render_jobs`。
- `static/common.js`：全局视频任务中心轮询。

维护要点：`video_generation.py` 已经是独立状态机，后续不要把生成阶段逻辑散回 `app.py`；质量报告是重试和人工验收的唯一可信依据。

### 3.8 平台适配与外部发布

- `adapters/base.py`：`PublishAdapter`、`PublishResult` 统一协议。
- `adapters/api_base.py`：Token/API 型平台基类。
- `adapters/rpa_base.py`：Playwright 登录态、Cookie、代理。
- `adapters/douyin.py`、`adapters/xiaohongshu.py`：国内平台 RPA 发布。
- `adapters/twitter.py`、`adapters/facebook.py`、`adapters/reddit.py`：海外平台 API/RPA 支持。
- `adapters/huimei.py`：慧媒适配。
- `ratelimit.py`：平台发布频控。
- `publish_readiness.py`：发布前可用性检查。

维护要点：平台实现必须只返回统一 `PublishResult`，不要让平台私有异常直接污染队列状态。

## 5. 数据核心

当前数据库仍是单 SQLite 文件：`data/logiflow.db`。核心表可以按以下域理解：

- 用户/权限：`users`。
- 发布运营：`accounts`、`queue`、`publish_log`、`audit_logs`。
- 知识与模板：`kb_categories`、`kb_documents`、`prompt_templates`。
- 素材库：`assets`、`asset_segments`、`asset_segment_tags`、`asset_processing_jobs`、`local_asset_import_jobs`。
- 热点库：`hotspots`、`hotspot_signals`、`hotspot_media`、`hotspot_sources`、`hotspot_fetch_runs`、`hotspot_event_clips`。
- 证据与样本：`brand_evidence`、`evidence_packages`、`sample_bundles`。
- 选题简报：`topic_briefs`、`topic_evidence_items`。
- 视频生产：`video_projects`、`video_project_revisions`、`video_generation_jobs`、`video_generation_events`、`video_render_jobs`。
- 模型成本：`model_routes`、`model_budgets`、`model_cache`、`model_usage`。

维护要点：数据迁移目前集中写在 `init_db()`；新增字段必须提供兼容旧库的 `_ensure_column()` 路径。

## 7. 当前收束判断

### 已经形成的稳定主线

1. 内容生产入口从“直接生成文案”升级为“对话/热点/选题简报”三入口。
2. 素材系统已经分成 Buffalo 原有素材库和热点素材库，热点母片再切成事件 Hook。
3. 视频生成已经从一次性渲染升级成持久化状态机，支持幂等、取消、重试、人工验收和质量门禁。
4. 发布侧仍保持统一队列和适配器协议，适合继续扩平台。

### 仍需克制的风险点

1. `app.py` 和 `database.py` 已经过大，新功能应优先落到独立服务模块，再由 API 调用。
2. `static/*.html` 仍是大文件内联脚本，UI 改动要用契约测试守住关键 DOM/API。
3. 热点素材权利状态、证据包、视频素材引用不能放宽，否则会破坏“可解释、可追溯、可发布”的底线。
4. Graphify 图谱是离线导航，不是运行时依赖；本次快照明确纳入当前未提交工作区。

### 最近改进日志进度（截至 2026-08-03）

已经完成：聊天视频首包真实验收、Hook 跨主题复用纠偏、渲染提速与数据库写入降频、双素材准入硬门禁、JWT/CORS 安全加固、此前未跟踪业务文件分批补交，以及认证/页面/配置/视频生成四组基础路由拆分。热点抓取已接入统一代理变量，BusinessTech 的 Cloudflare 拦截会降级为“受限”而不是错误。

当前停点：`app.py` 和 `database.py` 仍是两大耦合中心；聊天视频已统一到 `video_generation_jobs`（`chat_video_tasks` 表/DAO/410 shim 已退役）；热点匹配词表已收束到 `hotspot_lexicon.py`；真实抓取已验收；场景 TTS/FFmpeg 并发与取消多进程跟踪已落地；账号凭据已静态加密且存量明文已迁移；作业终态会同步 `video_projects.status`；证据包禁止标题/摘要自证；运营主张正则已收窄并支持已确认品牌证据放行；`model_call_cache` 具备 TTL/容量清理。后续可选：Commons 配图 403 重试、BusinessTech/The Citizen Playwright 过 Cloudflare、继续拆分 `app.py`/`database.py`。

本次 Graphify 全量快照已纳入当前未提交工作区，统计为 197 个代码文件、2,419 个节点、5,591 条聚类后关系、126 个社区，0 模型 token。

## 8. 后续改动落点建议

- 新 API：先在 `models.py` 定请求体，再在业务服务模块实现，最后在 `app.py` 挂路由。
- 新数据库能力：先补 `database.py` 表/迁移/DAO，再补测试；不要从前端直接拼接新状态。
- 新视频能力：优先扩 `video_generation.py` 阶段或 handler，不要绕过任务状态机。
- 新素材能力：优先接 `asset_processing.py`、`semantic_matching.py`、`media_retention.py`，不要让 `static/assets.html` 独自决定业务规则。
- 新发布平台：实现 `adapters/base.py` 协议，接 `publisher.py` 和队列状态。
